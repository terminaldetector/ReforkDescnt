# Snapshot fix: weapons, equipment, legacy generation and render isolation

User report is against 1.1.22-portals.1, Fabric API 0.116.17+1.21.1. Logs include runs
with and without Sodium, on Windows / RTX3060, without Immersive Portals. No model
loading exception or weapon stack trace was present. The screenshot of a horizontal
mirror showing sky alone is not proof of an incorrect reflection: object/occlusion tests
are required. Original private logs are retained locally, not copied into this repository.

## Implemented, awaiting final client acceptance

- LMB/RMB use a server-authoritative weapon controller. Existing held weapons work
  independently of socketed copies; both Fusion charge/release and continuous-use
  item lifecycles are preserved. GUI owns mouse while open. Building items keep their
  ordinary use actions. Auxiliary socket fires on B. G retains rocket mode selection.
- N opens a real handled drone inventory with a 3D hull preview: primary, secondary,
  auxiliary, spare tool, propulsion. Free flight stores actual items in player NBT;
  optional Pyro vehicles retain their existing persisted hardpoints. Equip/shift-click
  transfers items. Free-flight equipment drops with ordinary inventory on death unless
  keepInventory is enabled. Equipment mirrors are independent of server authority.
- 6DoF held items use fixed eye-relative poses without arm/equip/swing animation.
  Portal projector is centred. The hand pass avoids applying world bank a second time.
- Advanced generators, bands, infinite city and automatic legacy seed routines are
  retired. World creation shows disabled placeholders. Old registration/pack IDs remain
  loadable for saves; old terrain is not erased or rewritten. Advanced is not automatically
  enabled on fresh installs or from stale feature settings. Cubic Chunks remains a
  distinct native preset/runtime; no static copies or extra ship-interior dimensions.
- Horizon has no eye-centred cutout. It draws as a distant backdrop behind real geometry,
  before entities, transparent water and vanilla clouds. This does not introduce a new
  volumetric cloud simulation. Exact T-junction stitching and higher LOD detail remain open.
- Nested mirror/portal views flush pending outer geometry, isolate framebuffer/projection
  state and exclude cockpit duplicates. Nested Fabulous views use the normal opaque path
  to avoid writing the outer frame's shared transparency targets; outer graphics settings
  are retained. This needs actual Fabulous client verification.

## Validation record

The earlier hull-only stage passed 578 unit tests / 141 GameTests. A test fixture first
failed because the creative starter kit already contained a laser; its inventory is now
cleared before the conservation test. The current free-flight extension adds a sixth test
and has NOT inherited a pass from that earlier source. New actual-key client checks cover
primary/secondary fire, stable projector under roll, synchronized slots and the real screen.

Local Gradle was subsequently blocked before compilation by the execution sandbox denying
its local TCP listener (`java.net.SocketException: Operation not permitted`). The network
permission request returned no grant. Direct javac from cached dependencies is available;
CI is used separately and reports its exact revision. Never ship the earlier generated
root dist snapshot as if it passed this final source.

Dynamic Boarding, local block interactions, joints, ControlCore and full 3D combat AI
remain open in docs/v5/boarding. This snapshot does not close the master specification.
