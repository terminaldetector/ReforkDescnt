# Следующий этап: ship-UP и единый frame пассажира

Это результат инвентаризации, не отчёт о готовой функции.

- DynamicBodyAttachment сейчас задаёт box, gravity и jump через постоянный world-UP.
  Расширение должно хранить UP/ориентацию персонажа, выводить локальную гравитацию
  из позы корпуса и выполнять oriented narrowphase для игрока и world geometry.
  Широкая AABB годится только для broadphase, не для точного контакта с наклонной палубой.
- BodyMotion/BodyCollisionQuery уже дают pose-specific normal/point и v+ω×r.
  BodyContactConstraint сохраняет взаимную реакцию; новый режим должен использовать
  их же. Второй физический движок и тела для каждого неподвижного блока не нужны.
- FootGravityGeometryMixin, GravityMount.standingBox и FootGravityCamera содержат
  существующие адаптеры тела/глаз/камеры. ActorFrames сейчас поддерживает ограниченный
  набор мобов и исключает игрока; автоматического готового адаптера пассажиров нет.
- GravityMount.safeMount использует requestTeleport/setPosition и обнуляет скорость.
  Его нельзя вызывать каждый тик для посадки на корабль. FootGravitySystem.travel
  также имеет отдельную логику snapToSurface: её нельзя перенести в абордаж как follow.
- Сначала нужен один владелец frame между FieldGravity, Boarding и 6DoF. Frame и ввод,
  локальные глаза/лучи/рендер тела должны синхронизироваться согласованно с body-state.
  Только поворот камеры не меняет физическое тело и не закрывает требования.
- Новые игровые проверки: крен/тангаж через 90/180/360 градусов, потолок и узкий
  интерьер, столкновение головы, выключение локальной гравитации, прыжок и переход
  между двумя телами. Затем dedicated/two-client и сохранение состояния.
- Миграция существующего drmd:sky_ufo и полноценный 3D боевой AI продолжаются после
  физического frame; старая регистрация/команда сохраняются, параллельный UFO не нужен.
