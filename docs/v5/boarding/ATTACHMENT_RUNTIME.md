# Этап2b — первый серверный контакт игрока с BlockBody

Рабочий кандидат1.1.25-boarding.1. Это world-UP ходьба, не полный абордаж UFO.
Полная приёмка12+9 по-прежнему OPEN. Последний проверенный пакет до этого этапа —
1.1.24-boarding.2; рабочий исходник сам по себе не является проверенным компилятом.

## Реализация

- DynamicBodyAttachment хранит мировые feet/velocity и настоящий support contact.
  Геометрия берётся из локального compound BVH через BodyMotion: траектория корпуса,
  SAT, relative CCD и ограниченные угловые подшаги. Нет local-anchor-follow,
  requestTeleport, статической копии корабля или отдельного измерения.
- Игрок остаётся upright в обычной мировой гравитации. Ходьба использует powered
  tangential contact с конусом трения; корпус получает противоположный импульс.
  Прыжок добавляет vanilla .42blocks/tick =8.4world-units/second к уже имеющейся
  мировой скорости. Скорость поверхности не прибавляется второй раз.
- Сервер шагает пассажиров в END_WORLD_TICK после тел, в порядке UUID. Реакции
  применяются к существующему D6PhysicsBody, не создаются физические тела блоков.
  Support вычисляется по конечной геометрии с сантиметровым contact margin:
  старый признак начала последнего angular substep терял поддержку на38-м тике.
- Ready(1) включает протокол только для поддерживающего клиента. C2S передаёт
  ограниченный ввод с epoch/sequence, не координаты. Команды обрабатываются по
  одной за физический тик; очередь32, клиентская backpressure16, TTL4 тика.
  NaN, повтор, неверный epoch и скачок sequence отклоняются без изменения состояния.
- Во время server-owned режима обычные movement positions не управляют игроком;
  их finite-проверка и look сохраняются. Baseline vanilla и floating flag обновляются
  только для управляемого пассажира и при отпускании. Вне режима действует vanilla.
- Клиент предсказывает тем же мотором, повторяет неподтверждённый ввод от серверного
  состояния и исправляет ошибки через обычный Entity.move. Основной body-state
  содержит согласованную позу/скорость/угловой момент; snapshot привязан к измерению.
  Предсказание работает на числовых копиях и не меняет отслеживаемый клиентский корпус.
- Смена6DoF, исчезновение опоры, смерть, riding, жидкости и разрыв соединения
  отпускают управление. Возвращается актуальная мировая скорость; старые leases
  и weak references удаляются. Мобы и предметы пока этот runtime не используют.

## Проверка

Добавлены численные тесты реального мотора и серверные GameTests игрока: посадка,
ходьба/реакция палубы, отрыв, поддельные положения, недопустимый ввод, удаление тела,
переход в6DoF и отсутствие Ready. Client harness нажимает настоящие W/Space,
проходит C2S/S2C и снимает производственный renderer. Тот же код запускается в
обычном CI-мире и native BCC. Отдельный release gate требует свежих пяти сцен.

Первые неуспешные прогоны сохраняются в work/attachment; новые игровые результаты
не объявляются пройденными до финального exact-source прогона.
Полигон содержит управляемую тягу и yaw-stabilization настоящими импульсами и
моментами: свободная плита физически опрокидывается под пассажиром и при world-UP
не обязана удерживать его после выхода за угол трения. Положение/скорость корпуса
в ходе сценария не перезаписываются ради поддержки.

## Остаётся

- Локальная ship-UP гравитация, физический переход ориентации персонажа и свободные
  вращения корпуса с пассажиром по всем осям.
- Мобы/предметы, полноценные интерьеры и локальное редактирование/механизмы.
- Joints, ControlCore, большой действительный UFO и полный3D AI.
- Dedicated-server/two-client и persistence-приёмка; текущий integrated harness
  не закрывает соответствующие требования.

## Уточнения после первых игровых прогонов

Minecraft Entity.move пропускает delta²≤1e-7. Малые corrections без учёта этого
порога застревали в CCD; небольшой разрешённый separation=.0005 устраняет overlap.
Пропущенный короткий шаг до time-of-impact не считается столкновением со стеной
и не обнуляет мировую скорость. Два отдельных регрессионных теста используют
такой же порог движения, как Minecraft. Непрерывность server lease проверяется
во всех сценах до настоящего нажатия Space, а не только в конце интервала.

Ошибка предсказания измеряется по совпадающему acknowledgment/sequence: сохранённое
состояние после команды сравнивается с серверным результатом той же команды до
replay. Несинхронная выборка live-позиций разных тиков не является этой метрикой.
Проверка требует не меньше30 сопоставленных команд, ошибку<.8 блока и отклонение
мировой горизонтальной скорости прыжка<.03m/s. Численные результаты и свежие кадры
публикуются отдельно для точного source SHA.

Обычный клиент выявил отдельный startup-lag: пакетная обработка накопленных
серверных состояний при лимите correction=.2 на ввод оставляла игрока на несколько
блоков позади. Небольшая ошибка сглаживается; накопленное расхождение>.5 устраняется
до следующего предсказания через Entity.move с проверкой мировых коллизий. Это
коррекция по серверному состоянию, без локального якоря и без teleport-follow.

Тест повторного приземления также обнаружил ошибку собственного ввода: раннее
подтверждение прыжка переводило сцену раньше отпускания Space. Клавиша теперь
отпускается при переходе сцены; ожидание нового контакта ограничено120 тиками.
Это исправление тестового сценария, не изменение игровой силы прыжка.
