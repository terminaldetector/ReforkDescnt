# Этап2c: корабельная гравитация и ориентированный игрок

Рабочий кандидат1.1.26-boarding.1. Последний опубликованный проверенный пакет —
1.1.25-boarding.1. Этот документ не подтверждает приёмку нового кандидата.

## Реализация в рабочем дереве

BodyGravityField хранит ограниченный локальный объём и ускорение, привязанные
к существующему BlockBody. Поле по умолчанию выключено; операторская команда
`/d6body gravity <корпус> 0 -32 0` включает его, `0 0 0` выключает.
Это поле игрока, а не готовая общая гравитация всех мобов и предметов.

DynamicBodyAttachment хранит физический Quaternion персонажа и владельца
гравитации отдельно от контакта опоры. Прыжок внутри поля оставляет серверную
авторитетность активной. Локальный ввод protocol2 и состояние ориентации передаются
отдельно от world-space координат; старый клиент не получает движение нового codec.
Ориентация меняется ограниченно и проверяет место для головы. При выходе из поля
возврат в world-UP разрешён только с безопасной обычной геометрией.

Ориентированные shape casts используют тот же SAT/BVH и составные VoxelShapes
настоящего мира. Неизвестные XYZ/FULL объёмы закрыты; соседний halo проверяется до
вызова shape-provider. Коллизии считают точный OBB, не его широкую AABB. Проверенное
перемещение проходит через Entity.move; привязки к локальному якорю и teleport-follow нет.
Один snapshot геометрии служит подшагам; тела для неподвижных блоков не создаются.

BoardingPose согласует геометрию, глаза, камеру и модель, имеет отдельное
серверное spawn/late-join metadata. Поворот камеры сам по себе не считается
физическим поворотом персонажа. Старый GravityMount.safeMount не используется.
Корабельная гравитация и обычный FootGravity не интегрируют игрока одновременно.

## Локальные результаты кандидата

619 численных тестов,160 серверных GameTests и37 Python-проверок прошли.
Native BCC GL3.2 без Sodium прошёл все13 сцен:588 подтверждённых команд,
максимальная ошибка предсказания0.008801 блока,481 реальных model/camera проходов.
Ошибка UP модели0, камеры0.000280, прыжка менее1e-10 м/с. Это локальный прогон
рабочего дерева; точные source/JAR и повторные прогоны фиксируются отдельно в релизе.
CI нового source и обычный/Sodium клиенты этим документом ещё не подтверждены.

Первый WIP28c4c8f сохранён GitHub Actions40749827680. Архив исходников сохранён;
численная регрессия ускоренного тангажа упала на7-м тике. Этот run не сертифицирован.
Исправлена скорость реальной вращающейся точки опоры и COM персонажа. Контактная
плоскость учитывает вращение обеих сторон, а весь Quaternion персонажа наследует
вращение корпуса. Это устранило орбитальный дрейф ног в полном цикле манёвров.
Вместо интерполяции мировых Euler-углов камера интерполирует локальный обзор;
F5 ограничен реальной геометрией корпуса и после выхода из boarding.

Ранние native сбои сохранены: named tick() в remapped тестовом JAR, ошибочная
начальная высота головы, потеря опоры на тангаже, дрейф кромки отверстия и команда
без прав оператора в одноразовой фикстуре. Производственная команда остаётся OP2;
оператором стал только тестовый пилот. Обнаруженный в долгом неуспешном прогоне
нетикающий корпус теперь имеет неподвижную контактную поверхность. Его сохранённый
импульс не стирается и доступен после возобновления физических тиков; клиент получает
этот статус вместе с авторитетным snapshot и не экстраполирует остановленное тело.
Проверки не создают чанки и не телепортируют персонажа за кораблём.

## Требования к доказательствам

Новый runShipboardingcheck выполняет настоящие W/Space, 360° крен, 360° тангаж,
комбинированное вращение трёх осей, прыжок под корабельной гравитацией, выключение
поля настоящей командой и H/toggle. Требуются13 сцен,250 подтверждённых команд,
реальные вызовы производственных model/camera passes и ограниченные ошибки.
Прежние пять world-UP сцен и вся оружейная/инвентарная/рендерная регрессия остаются.

Полный UFO, корабельные механизмы/редактирование, пассажиры-мобы/предметы, joints,
ControlCore, dedicated/two-client и полноценный3D AI ещё не реализованы. Все12+9
критериев целиком остаются OPEN.

## Регрессия старых сценариев

CI40755317546 прошёл unit/GameTests, оружие, snapshot, Fabulous и LOD; старый
world-UP сценарий остановился на сравнении игрока с корпусом из разных временных
линий. Оба boarding harness теперь измеряют локальный путь по одному серверному
snapshot без расширения допустимых пределов.

CI40755901352 остановился на сравнении двух кадров неба (9738 пикселей различия).
Сохранены оба исходных изображения. Для такого попарного сравнения новый harness
задаёт вход ориентации перед каждым кадром, проверяет положение камеры до расчёта
terrain и равенство матриц on/off. Вложенные mirror/portal кадры исключены из захвата.
Локально10 поз/20 изображений прошли с нулевой разницей при взгляде вверх;
предел100 пикселей и проверка матрицы terrain не изменены. Изменён тестовый код,
производственная геометрия LOD этим исправлением не меняется.
