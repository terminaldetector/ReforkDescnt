# Этап2a.2 — неподвижный корпус перестаёт повторять старый поворот

Осмотр native BCC-кадров1.1.24-boarding.1 после успешных численных проверок выявил
дефект отображения: previousRotation обновлялся только при изменении POSE, а
BlockBodyRenderer каждый кадр заново делал slerp(previous,current,partialTick).
Когда поворот закончился и POSE перестал меняться, partialTick продолжал сбрасываться
каждый тик, возвращая корпус к прежнему углу. Физический quaternion при этом уже
стоял на месте; два клиентских кадра показывали различную ориентацию одной палубы.

BodyRotationTimeline использует абсолютное время age+delta. По окончании двух тиков
он держит полученную ориентацию. Первый spawn использует полученный угол сразу;
новая цель начинает интерполяцию от последнего показанного угла. Velocity-only
пакеты, повторная камера и эквивалентные q/-q не перезапускают старый поворот.
Это только отображение: серверная физика, collisionQuery и контакты используют
авторитетную ориентацию. Полное предсказание движения корпуса/пассажиров остаётся OPEN.

Добавлены6 численных регрессий. Native harness выполняет поворот палубы после её
появления у клиента и проверяет quaternion, реально переданный MatrixStack.multiply
производственным BlockBodyRenderer. Не менее50 завершённых кадров должны показывать
остановившийся угол. Это не отдельный тестовый renderer и не проверка только getter.

Версия кандидата:1.1.24-boarding.2. Пакет1.1.24-boarding.1 сохранён неизменным.
Точные SHA, результаты контрольного прогона старого JAR и нового клиента сохраняются
в отдельном отчёте после проверки. Все критерии Dynamic Boarding/UFO остаются OPEN.
