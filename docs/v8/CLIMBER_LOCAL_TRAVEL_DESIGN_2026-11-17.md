## 2. Dry force operator and material/effect preservation

Let u be unit local UP and R be the existing ActorFrameMath local-to-world basis. Let m be the exact vector returned by native applyMovementInput after native movement and collisions, t the native pre-move tangent damping coefficient, n=.9800000190734863 (the audited non-Flutterer native normal damping), and a be the exact three final setter arguments already computed by vanilla, including its levitation/gravity/other upstream adjustments. Define:

    Dworld(m) = (t*m.x, n*m.y, t*m.z)
    residual = a - Dworld(m)
    corrected = R * diag(t,n,t) * inverse(R) * m + residual

Thus only the native anisotropic damping operator changes basis. The original effect contribution is retained as an actual world-space residual rather than discarded, recomputed or retimed. Correcting levitation's own orientation is a separate unproved feature. The existing field gravity/.86ground/.96air update remains unchanged. There is no hardcodedtarget speed, tangent zeroing, rotation of the actor's position/current velocity before native collision, or second movement integration. External impulses present in m are dissipated by the same material operator as ordinary motion, not replaced with AI motion.

Native hasNoDrag uses its untouched setter1193 and does not enter this correction. Fluid/lava/elytra exits never reach the dry hook. The existing Flutterer normal-factor alternative must not be broadened into a family classifier; nativeSpider/Cave do not implementFlutterer. If an unobserved modded subclass differs, delegate rather than assume the normal coefficient. Read material through the real support face, so native movement acceleration and tangent drag both use the same slipperiness, including ice/slime/honey and block overrides. Do not cache a previous material across movement/field ticks.

A fresh loaded support snapshot can be sampled at the material seam once per dry travel: actual actor box plus existing1.6m contact ray/1m availability halo, <=64XYZcubes, normal>=.95, feet gap[-1e-6,.08], actual clear body and no unsupported moving hull. Reuse existing WorldAccess.isVolumeAvailable; no load/ticket/generation calls. Store only the BlockPos/current travel context; do not hold world maps. No support means air: do not manufacture onGround or pretend the previous block remains support. Unknown/overbudget/unsupported geometry means the adapter declines this increment; it is never declared AIR/grounded by the adapter. Existing native unknown-volume safety is a distinct open issue and no streaming proof is claimed.

### Collision boundary needing explicit scope approval

For the six cardinal UP frames, R is a signed permutation, so the local operator cannot resurrect a velocity component zeroed by native axis collision. For arbitrary oblique UP, conjugated anisotropic drag can mix world axes and create a component into an already resolved contact. Existing native booleans alone do not provide adequate signed contact normals. The MINIMAL SAFE FIRST INCREMENT should therefore bind this dry correction to six cardinal frames (axis alignment within1e-6), leaving oblique contact/dissipation unchanged and explicitly open. Pure algebra may be tested for any normalized frame, but that is not oblique collision acceptance.

An alternative oblique-contact extension would need actual native requested/resolved SELF movement and signed active constraints, then projection of only the new damping correction against those constraints. That would add a separate LivingEntity.applyMovementInput movement seam and its own genuine negative/collision tests; it is not included or authorized by this proposal. Do not infer normals from onGround/horizontalCollision alone or zero all tangent velocity to hide the issue.

## 3. Preserve native pounce behavior, correct its frame

Use the goal's stored target field, not a new target query or waypoint command. Vanilla canStart already owns passenger exclusion, target lookup, rotation-invariant squared distance4..16, actual onGround check and Random.nextInt(toGoalTicks(5)); shouldContinue returns !onGround. Preserve these byte-for-byte and preserve normal goal interruption of the path.

Let d = (target.position - mob.position) projected onto the plane perpendicular to u, and vt = existing world velocity projected onto that same plane. For d.lengthSquared()>1e-7, the exact native tangent expression becomes .4*normalize(d)+.2*vt. Add u*(double)goal.velocity, where the native float0.4 is0.4000000059604645 as a double. This preserves the native inherited tangent coefficient and actual target direction; it does not set all velocity tozero, force a route or rotate alreadyworld-space displacement twice. For the <=1e-7 branch, vanilla retains tiny raw d without the inheritance term; retain that explicit native degeneracy rather than inventing a new impulse policy. A separate parity case must document it; the normal first proof uses nondegenerate tangent separation.

The jump must physically detach when space allows. Do not setOnGround(true), pull it back by stronger snap, suppress PounceAtTargetGoal, replace its target with a path node, or cancel native selection to keep a continuously grounded test green. Local gravity then produces the real airborne arc, native world collision resolves it, and measured support reacquisition restores ordinary grounded navigation through the existing lifecycle. Pounce correction may be limited to the same six cardinal first-increment scope; other orientations remain explicitly unproved.
