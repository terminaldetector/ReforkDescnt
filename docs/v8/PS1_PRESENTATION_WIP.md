# PS1 presentation — independent work in progress, 9 November 2026

The user's parallel-render request is implemented on isolated branch `experiment/render-ps1-20261109`, based on `06260bd`. The existing BlockBody/physics branch is independent. This is an initial S05-T01/T04/T05 increment; none of S04/S05 or complete master v8 is accepted by this document.

## Current implementation

`HYBRID_NATIVE` remains the default for old and new configurations. A runtime settings row selects Native, PS1 Hybrid or a world-wireframe Debug profile, and separately cycles the PS1 scene height. Choices persist in the existing client properties file. The independent `hybridRender` and server physics choices are untouched. At 16:9 the default produces a real 640×360 scene target; other window aspects preserve their FOV/aspect. Small windows are never supersampled. Minimized windows, GPU texture dimensions and a four-million-pixel allocation ceiling are bounded.

One redirect wraps only the existing `WorldRenderer.render` call. PS1 borrows a private scene framebuffer, then copies its colour and depth to the original target with nearest filtering. Vanilla hand, crosshair, text, menus and HUD render afterwards at native resolution. Native bypasses target borrowing. Debug changes the world polygon raster only, restoring both front/back modes before hand or overlays; it is wireframe debug, not yet the specified normals/LOD/collision visualizer.

Custom 6DoF weapon, cockpit and Mega Beam callbacks currently live inside world events. They are deferred for PS1/Debug until after the scene is composited. Each queued callback copies Fabric's reusable context, matrix stack, projection/model-view matrices and the current depth/write/cull/blend policy. The original stack may be popped or the Fabric context reused by a nested mirror before the deferred pass; references to those mutable matrices are therefore not retained. Consumer buffers remain the same live provider and are flushed immediately on the restored native target.

Fabulous transparency and entity-outline processors have private cached low-resolution equivalents. Original auxiliary targets are borrowed/restored, never resized or closed. The private outline composite runs once in the scene; the later ordinary outline call is skipped only for that already-composited frame. Mirrors/portals continue their independent pass and use the current outer framebuffer's raster dimensions, including low-resolution scissor coordinates. Nested view targets restore the borrowed low-resolution processors before the outer scope restores the original full-resolution processors.

The render scope uses try-with-resources. Original target references and viewport return before hand/HUD drawing even if the world render throws. Target creation failures report a diagnostic and render at Native until a profile toggle or resource reload, without modifying the saved choice or skipping the world. The native gate explicitly rejects such fallback as PS1 success. Resize/profile/world/resource changes release only private targets. The near mesher, geometry cache, world storage, colliders and simulation state are not rebuilt by a presentation change.

## Verification performed

Source `f1ceebd` successfully compiles all main Java and passes **five targeted PresentationOptions tests**, zero failures/errors/skips. This was the first compile, with no earlier compiler failure. The exact log, source SHA and JUnit XML are retained in the isolated worktree's `work/ps1/`. These tests are not graphics proof.

The later `NativePresentationCheck` is an independent production-classpath Cubic harness under flag `drmd.gate.presentation`, with proposed marker `presentation-ok.json`. It authors an ordinary checker/iron backdrop, a merged mirror and gold wall behind the camera only in the disposable copied world, with a real 6DoF laser/cockpit. Six fresh scenes exercise Native → PS1-360 → Native → Debug → PS1-180 with a real 960×540 window resize → Native/window restoration. It checks real scene/output dimensions, a one-physical-pixel HUD witness, nearest world pixel groups, eligible deferred viewmodel callbacks, actual reflected gold pixels and a mirror draw diagnostic, main FBO/viewport restoration, unchanged representative blockstore/hybrid choice and zero GL errors/fallbacks. A deliberate exception inside a real presentation scope checks restoration of all eight original auxiliary target references. Actual saved screenshots still require inspection; draw counts alone are insufficient.

The first complete harness compilation succeeds on `dc3cd83` (19 seconds, no compiler failure). The fixture also includes an actual glowing husk for outline rendering. That native harness has not yet been launched or accepted. Build/test/native processes are sequenced with the main work to avoid concurrent memory pressure and confusing source/artifact provenance. The initial integration still requires fresh same-source full regressions, current JAR hashes, and real GL3.2 plus Sodium frames, including Fabulous/outline and viewmodel checks. The blockstore check covers a representative authored front wall; together with the enabled-flight assertion it is not universal world/physics/cache-invariance acceptance.

Candidate build and launch helpers are `scripts/v8/ps1_build.sh` and `ps1_native.sh`. They resolve their own worktree, bind the exact committed source and launcher inputs to both CRC/hash-checked candidate artifacts, and verify bytes before every launch. Staging uses the existing official stager with immutable library hardlinks and an explicitly named main-runtime Minecraft-only intermediary cache. Raw official Minecraft hashes match both manifests and both actual source files; no cached DRMD code, save or test marker is borrowed. Every scenario gets independent inputs, log, exit, fresh runtime, six frames and marker. Suggested first scenarios are `ps1-sodium` and `ps1-fabulous-gl32`. Helpers are syntax-checked but have not yet run a JAR build or native test.
