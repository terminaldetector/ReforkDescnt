# Хранилище LOD (Этап 6, первый срез)

Модуль `world/store` — независимый: интерфейс из пяти методов, ни одного типа Minecraft в нём,
тестируется без игры. Первый потребитель — воксельный горизонт, который теперь рисует **тот мир, над
которым летали**, а не только правдоподобный.

```
SectionStorage          пять методов, байты по ключу
├── MemorySectionStorage        карта в памяти (клиент, тесты)
├── FileSectionStorage          файл на секцию под <мир>/drmd/surface
└── CompressedSectionStorage    Deflate поверх любого другого

SectionKey              (уровень, x, z) → long
SurfaceSection          32×32 ячейки: высота + цвет
SurfaceStore            загрузка по требованию, вытеснение, перестройка уровней
SurfaceIngest           чанк → ячейка (сервер)
SurfaceStreamer         секции игрокам, каждая по одному разу
```

## Три решения, которые определяют остальное

**Ячейка нулевого уровня — ровно один чанк (16 блоков).** Тогда одна загрузка чанка даёт одно число
для одной ячейки и **заменяет** его. При более крупной ячейке чанк покрывал бы её четверть, три
других пришлось бы помнить, и дешёвый способ их совместить — бегущий максимум, который не умеет
опускаться. То есть снесённая башня осталась бы на горизонте навсегда.

**Грубые уровни перестраиваются, а не накапливаются.** Свежая секция, четыре ребёнка сворачиваются в
неё, самый высокий из 2×2 выигрывает (горизонт — это силуэт, усреднение башни с полем рядом теряет
ровно то, ради чего он нужен). Поэтому уровень умеет становиться ниже — это условие для Этапа 10.

**Перестройка идёт снизу вверх, по одному уровню за проход.** Секция, которую только что собрали,
помечает своего родителя. Пометить сразу всю цепочку выглядит эквивалентно и не является таковым:
множество грязных не упорядочено, уровень 2 может собираться раньше уровня 1, не найти детей, молча
не собраться — и он уже удалён из множества, чинить некому. Дальние кольца горизонта остались бы
пустыми навсегда. **Это поймал тест, а не игра.**

## Стриминг

Секция уходит игроку **один раз**. Клиент хранит полученное, рельеф, который никто не менял, второй
раз не нужен — трафик у стоящего игрока падает в ноль. Окно: 3 секции по каждому уровню вокруг
пилота (уровень 1 — километр, уровень 6 — тридцать), 6 секций за проход раз в секунду.
`invalidate(key)` вернёт секцию в очередь, когда земля изменится — это понадобится Этапу 10.

Для сравнения, что было в удалённом конвейере: 625 ячеек с высотой, цветом и флагами **каждый тик
каждого игрока**.

## Чего здесь нет

- Регионного формата: файл на секцию, ~1 КБ после сжатия. Компактная упаковка — это ещё одна
  реализация `SectionStorage` и ничего выше не меняет; ради этого интерфейс и узкий.
- Воксельных секций: сейчас поверхность — высота и цвет, без навесов и внутренностей. Воксельная
  секция встанет в тот же стор под теми же ключами, когда будет чем её рисовать. Место под Y в ключе
  уже оставлено.

## Тесты

`SurfaceStoreTest` — 11 тестов, гоняются в CI: упаковка ключей (включая отрицательные координаты и
floor-деление), сериализация секции, отказ читать чужой формат, силуэт при сворачивании уровня,
прозрачность сжатия, спуск грубого уровня вслед за снесённой землёй, переживание перезапуска.
