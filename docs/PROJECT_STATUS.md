# Состояние DRMD

Документ фиксирует рабочую базу и границы готовности. При расхождении старые заметки о ветках,
прогонах и версиях не являются обещанием текущей сборки.

## Единая целевая база

- Minecraft **1.21.1**, Fabric Loader, Java **21**. Metadata закрепляет Minecraft как `~1.21.1`;
  Minecraft 26.3 не входит в диапазон совместимости.
- Один Fabric-мод `drmd-6dof`, собранный Gradle. Совместимость клиента и сервера требует одной версии
  JAR и Fabric API.
- Проект строится как самостоятельный 6DoF Descent/Prey-проект на Minecraft как технической основе.
  Меню, визуальные правила и физика принадлежат проекту.

## Уже подключено

- 6DoF с локальным предсказанием, серверной коррекцией, инерцией и посадкой в Pyro GX.
- Pyro — отдельная сущность-корпус; пилотская модель скрывается на всех клиентах, пока игрок едет
  в корпусе. В открытом воздухе выход из корабля не запускает повторную посадку.
- Векторная локальная гравитация, факелы и магнитные аномалии. Оторванные ракетой деревья/колонны
  следуют полю факела или генератора и могут осесть на полу, стене либо потолке; воксельное/четвертное
  разрушение поддерживается только перечисленными адаптерами и блоками. Поля из разных измерений
  имеют независимые идентификаторы и не перезаписывают друг друга при переходе через портал.
- Экспериментальный hybrid mesher для явно помеченных органических блоков и жёстких повреждённых
  блоков. Полный автоматический NoCubes-рендер природного мира ещё не включён.
- Собственные порталы для перехода и зеркала для отражения разделены архитектурно. Рендер через
  поверхность остаётся экспериментальным; геометрическая маска и глубина не завершены.
- Клиентские параметры доступны из меню DRMD, сгруппированы по назначению и прокручиваются на
  коротком окне. Там открыты обе опции горизонта/DH и виртуального корпуса НЛО.
- Экран генерации мира сгруппирован по высоте, шаблону, содержимому и экспериментальному хранилищу.
  Vanilla временно подавляет шесть функций генерации, но сохраняет их выбор для возврата в Advanced.

## Физические тела и ragdoll

- Умерший DRMD-дрон заменяется отдельной пятисегментной `RagdollEntity`: сервер считает массу,
  инерцию, вращение и ball-socket joints, а клиент получает позы частей и рисует их раздельно.
- Части сталкиваются с загруженным ванильным миром, падают по обычному либо локальному полю
  гравитации, сохраняются в NBT и имеют ограниченное время жизни.
- `PhysicsTarget` объединяет ragdoll и `BlockBodyEntity` для точного raycast и мирового импульса.
  Поэтому снаряды, hitscan, взрывная волна и существующая гравирельса больше не содержат отдельную
  физическую подделку для каждого типа объекта.
- Это ещё не универсальный humanoid-ragdoll и не физика тысяч тел: rig пока один (scout drone),
  столкновения тело-тело, сон/LOD и разрыв суставов остаются следующими этапами.

## Cubic-архитектура: фактическая граница

Есть симметричная XYZ-адресация 16³, разреженные объёмы, палитровое хранение и физические сборки
из ограниченного списка инертных блоков. Отдельный адаптер по желанию пишет рядом с миром снимки
уже загруженных ванильных секций; настройка доступна в меню генерации мира.

Это **не** замена ванильного жизненного цикла чанков. Генерация, загрузка, свет, высота мира,
сетевые пакеты, тики блоков и основной клиентский рендер всё ещё принадлежат ванильной колонной
модели. Снимки не дают высоту ±100 000 блоков и не превращают `BlockBodyEntity` в полноценную физику
Create. Текущие ограничения и этапы миграции собраны в
[`architecture/CUBIC_MIGRATION.md`](architecture/CUBIC_MIGRATION.md).

## Дальний обзор и модель Pyro

Distant Horizons — рекомендуемая мягкая зависимость для настоящих дальних LOD. Встроенный воксельный
горизонт остаётся отдельным процедурным обзором поверхности, а не LOD полного объёма; см.
[`DISTANT_HORIZONS.md`](DISTANT_HORIZONS.md) и [`VOXEL_HORIZON.md`](VOXEL_HORIZON.md).

Модель Pyro сейчас процедурно собрана из деталей Minecraft. Точная DXX-сетка исключена из активного
плана закрытия незавершённых подсистем и не является блокером сборки: в репозитории нет её
экспортированной геометрии и текстур. Тема может вернуться только с готовым OBJ/GLB/POF-ассетом;
до этого код модели не имитирует наличие оригинала. См. [`MOVEMENT.md`](MOVEMENT.md).

## Сборка и проверка

Из корня репозитория под JDK 21:

```bash
./gradlew test
./gradlew runGametest
./gradlew build
```

Сборка JAR сама по себе не доказывает корректность перспективы зеркала, поведения DH на высокой
дальности или запуска в Minecraft 26.3. Для них нужен совместимый клиент 1.21.1 и визуальная
проверка.
