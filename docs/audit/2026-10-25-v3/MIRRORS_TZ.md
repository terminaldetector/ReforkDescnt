# ТЗ для Codex F — ЗЕРКАЛА / MIRROR RENDERING

**Изолированная подсистема, не смешивать с порталами, HUD и общими боевыми VFX.** Связь с видео `dugsandshit.mkv`: 01:18–01:26, 04:31, меню `Отражения в зеркалах: Выкл`. Это **подтверждённое наличие UI-настройки**, а не доказательство работающего или сломанного зеркала. Основной аудит: [`UNGRAVITY_VIDEO_AUDIT.md`](UNGRAVITY_VIDEO_AUDIT.md), UG-022. Приоритет P2 для аудита, поднять до P1 при воспроизводимой неисправности заявленной фичи.

## Что проверить прежде, чем менять код
- Найти реальные классы материалов/блоков зеркала, renderer, client hooks, feature flag и сохранение настройки; зафиксировать commit и связь с JAR в записи.
- Определить ожидаемый продукт: настоящее динамическое плоское отражение, кубмап, статичная текстура или ещё только UI-заглушка. Не придумывать функционал сверх актуального проектного замысла.
- Запустить тестовую сцену с одним зеркалом, статическим ориентиром и движущимся entity. Снять video/screenshot **при ON и OFF**. Если зеркала фактически не реализованы, зафиксировать честный статус `not implemented` вместо `fixed`.

## Render-path и инварианты
1. Отражённая view matrix из мировой плоскости зеркала, а не просто разворот yaw на 180°. Сохранение правильной ориентации при свободном **6DoF pitch + yaw + roll**, включая инверсию и полюса.
2. Корректные clip plane/oblique near-plane и stencil/depth: объекты за плоскостью зеркала не просвечивают в неверную сторону; не рисовать лицевую поверхность зеркала как преграду самому render pass.
3. Handedness reflection, triangle winding, face culling, normal/lighting и тени (насколько поддерживается выбранным shader path).
4. Dynamic entities/дроны и частицы отражаются согласно области видимости, без двойников в обычной сцене. При движении камеры нет задержанного/frozen кадра, ghost trails, неверной проекции.
5. При выключенном режиме render target и дополнительные passes НЕ выделяются/не выполняются. При включённом, но вне кадра, зеркальный pass пропускается.
6. Защитить рендер от рекурсии зеркало-в-зеркало. По умолчанию разумный лимит отражения 1 проход, более глубокая рекурсия лишь если предусмотрена реализацией и выдержан frame budget.
7. Управляемая детализация отражения, ограничение targets, явная очистка GPU-ресурсов при unload/resize/world change; не портить основной framebuffer, HUD и LLOD.

## Матрица тестов и приёмка
- Плоскость зеркала: вертикальная и горизонтальная, если допускает блок/материал; вращение камеры roll=0°/90°/180°/270°; взгляд на край/за плоскость.
- Ориентиры перед/за зеркалом, один дрон/моб в отражении, смещение/поворот 6DoF, смена day/night и высотного слоя.
- ON → OFF → ON, переход на другой экран/мир, unload/reload чанка, возврат к отражению; не оставлять чёрных/frozen render targets.
- Одно зеркало, два параллельных/встречных зеркала, несколько вне поля зрения; telemetry: render passes/frame, GPU time, VRAM, FPS baseline vs enabled.
- **PASS:** направление отражения математически соответствует сцене, нет артефактов depth и culling, выключение действительно прекращает mirror passes, нет рекурсивной лавины и нарушений обычного 6DoF.
- В отчёте Codex: путь к классам, воспроизведение, root cause (если подтверждён), commit, скриншоты ON/OFF, числа производительности. Без фиктивного `fixed` по факту компиляции.

## Жёсткие границы задачи
**Не реализовывать и не менять:** переход сущностей между мирами/поверхностями, парные portal transforms, teleportation, player mount/unmount, портальные FBO, физику других блоков. Совместный renderer helper допустим лишь после независимых тестов и при отсутствии регрессии.
