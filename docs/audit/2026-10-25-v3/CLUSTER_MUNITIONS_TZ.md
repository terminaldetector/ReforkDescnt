# K — Кассетные боеприпасы / Cluster munitions

**Пользовательское требование:** исправить кассетные боеприпасы, не путать с обычными бомбами или огненным VFX. **P1**. Видеосюжеты массовой бомбардировки — около 11:00–12:30 и 16:00–19:29; по одному видео нельзя надёжно определить root cause сбоя.

## Что уже существует в найденной ветке
- `world/bombardment/AerialBombEntity.java`: `dispenseCluster` выпускает 7 обычных и 14 тяжёлых суббоеприпасов; у тяжёлого типа разброс сферический, у обычного — преимущественно вперёд по вектору падения.
- Триггер раскрытия: трассировка до поверхности по направлению движения/гравитации, или превышение порогов скорости/возраста; дополнительная ветка при контакте с землёй.
- `configureSubmunition(OrdnanceType.TNT_BOMB, ...)` и взрыв/поджог дочерней бомбы. Это исходный дизайн, не свидетельство правильного поведения в JAR.
- `BombardmentItems.java`, `OrdnanceType.java`, `AerialBombRenderer.java` и `SmokeSystem` совместно обслуживают эту подсистему.

## ТЗ
1. Зафиксировать фактическую матрицу типов (обычный, тяжёлый, управляемый, ракета) и явно разделить **submunition count, scatter, launch axis, fuse, arming delay, damage radius, crater, fire**.
2. Проверить раскрытие: большой/малый Y, низкая/высокая скорость, полный крен 6DoF, локальное направление тяжести, столкновение с поверхностью, жидкость, отсутствие ground hit (void), unloaded chunk. Отдельно наклонная траектория, не подменять world-Y.
3. Каждая кассета раскрывается **ровно один раз** и **не становится бессмертной**; каждый дочерний боеприпас получает корректный owner/type/velocity/fuse/serialization. Срабатывание при касании, timer, потеря владельца, pause/reload, удаление чанка; исключить повторное раскрытие, infinite fragments, дети спавнят детей.
4. Не превращать дробление в одну гигантскую сферу взрыва. Проверить распределение попаданий и локальных воронок; разделить эстетическую плотность от урона и серверной стоимости.
5. Лимит на количество живых дочерних entities по миру/чанку/tick, серверный budget, агрегация дальних VFX и decay/debris. Не создавать лавину `createExplosion`+world block update без ограничений.
6. При использовании в мирных условиях учитывать игрока, других мобов, водные зоны, инфраструктуру построек, дальность от серверных игроков, permissions/claims если поддерживаются.
7. Сценарии с дронами, артиллерией, бомбовым отсеком, прицелом/laser designator должны использовать единый, проверенный API расчёта цели и направления.

## Приёмка
- `count` обычная 7, тяжёлая 14 **по текущему дизайн-коду** или обновлённая явно согласованная спецификация; spawn count и detonation count наблюдаемо сходятся с лимитами.
- Нет исчезновения кассеты без эффекта, бесконечной кассеты, повторного раскрытия, коллизий на старте, висящих бомб после unload/reload.
- Данные `entities spawned/despawned`, TPS, explosion/block updates, screenshot/video scatter heatmap, трассировка типичных сценариев до/после.
