# O — Физика / Expanded profile как стандарт по умолчанию

**Явное требование автора:** игровой профиль физики **EXPANDED** является режимом по умолчанию. Переключение в настройках отдельно от Hybrid Renderer. **P1**. Не воспринимать это как автоматическую готовность ещё не завершённого ragdoll или тысяч физических сущностей.

## ТЗ
1. Аудит доступных физических систем: стандартная коллизия Minecraft, блоки/обломки, импульсы от оружия, гравитационные поля, manipulation/rail weapons, ragdoll (если реализован), local gravity, 6DoF world-to-local transform. Определить реально подключаемый состав Expanded, статус `implemented/partial/stub`.
2. Ввести отдельный enum/preset `STANDARD` и `EXPANDED` (при наличии других сохранённых режимов мигрировать через compatibility adapter). **Новый мир / новый профиль / отсутствие ключа → EXPANDED**.
3. При явно выбранном `STANDARD` — уважать выбор пользователя, не возвращать `EXPANDED` на каждом запуске. UI должен отображать текущее эффективное значение, а не желаемый default.
4. **Server authoritative** выбор физики для singleplayer/integrated server и выделенного сервера. Не допускать ситуации, когда клиент пишет EXPANDED, а коллизии/взрывы исполняются в STANDARD. При server lock UI показывает эффективный профиль и причину.
5. Все physics flags (ragdoll, block body, gravity manipulator, projectile impact, chunk debris) должны иметь bounds: caps per tick, sleeping/static states, broadphase, chunk-unload cleanup, time budget, collision groups. Это особенно важно для 100+ дронов.
6. Expanded-физика обязана сохранять стандартные safety-инварианты: player не зависает в entity после выходa из 6DoF (UG-001), смерть/respawn/teleport восстанавливают valid state, нет падения в void через сбой коллизии (UG-002).
7. Установка нового default **не должна** незаметно менять физику старых сохранений без понятного миграционного поведения. Определить политику per-world и при конфликте сохранений явно показывать совместимость.
8. Физика независима от Hybrid Renderer: 4 сценария `HYBRID ON/OFF × EXPANDED/STANDARD`, включая сохранение/повторный вход/мультиплеер если предусмотрен текущим проектом. Приоритет локального/offline режима; не вводить сетевые функциональности ради одной настройки.

## Исходники и оговорка
- В найденной GitHub ветке `physics/GravyPhysics.java` содержит физику гравитационных импульсов, **но не доказывает наличие Expanded profile**; `client/config/DescentConfig.java` не имеет ключа expandedPhysics. Это новый/восстанавливаемый продуктовый invariant, требующий реализации и QA.

## Приёмка
- Fresh config: **Физика: Expanded**; старый конфиг без ключа мигрирует согласно явной политике; пользовательский выбор `STANDARD` сохраняется.
- На сервере и клиенте совпадает эффективное состояние; полёт, коллизии, гравитация, бурение и боевые эффекты проходят smoke tests; нет непредсказуемых массовых spawn / TPS collapse.
