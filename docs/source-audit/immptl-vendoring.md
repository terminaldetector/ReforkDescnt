# Вендоринг Immersive Portals

*Что перенесено, куда, и как переносить дальше.*

Исходники ImmPtl 6.0.6 под Minecraft 1.21.1, ветка `1.21` — **Apache-2.0** (см.
[`license-map.md`](license-map.md), там же разбор ошибки, из-за которой сначала было записано
GPL-3.0). Копировать можно с сохранением уведомлений; DRMD остаётся MIT.

## Правила, по которым это делается

**Вендоренный файл целиком под Apache-2.0.** Пакет `com.terminaldetector.drmd.vendor.<проект>`,
шапка с лицензией, копирайтом и списком изменений — этого требует раздел 4 Apache-2.0. Граница
лицензии = граница файла. Смешивать чужой код с MIT-кодом внутри одного файла нельзя: тогда
непонятно, что именно под какой лицензией.

**Переносится то, чего нет.** У DRMD уже есть `PortalTransform.Quat` и `PortalTransform.rotationBetween`
— причём последняя **лучше** донорской: у ImmPtl в `getRotationBetween` прямо написано «не работает,
когда векторы коллинеарны», а у DRMD для этого случая назван запасной оси. Копировать поверх такого
было бы шагом назад.

**Проверяется числом, а не глазами.** Файл, переведённый с чужих маппингов, компилируется независимо
от того, сохранилась ли математика. Каждое ожидаемое значение в тестах посчитано отдельно до того,
как было записано.

## Перевод маппингов

Исходники ImmPtl — под Mojang-маппингами, DRMD — под Yarn. Таблица, чтобы следующий кусок был
механическим:

| Mojang (ImmPtl) | Yarn (DRMD) |
|---|---|
| `net.minecraft.world.phys.Vec3` | `net.minecraft.util.math.Vec3d` |
| `net.minecraft.world.phys.AABB` | `net.minecraft.util.math.Box` |
| `net.minecraft.core.BlockPos` | `net.minecraft.util.math.BlockPos` |
| `net.minecraft.core.Direction` | `net.minecraft.util.math.Direction` |
| `net.minecraft.core.Vec3i` | `net.minecraft.util.math.Vec3i` |
| `net.minecraft.nbt.CompoundTag` | `net.minecraft.nbt.NbtCompound` |
| `net.minecraft.nbt.Tag` | `net.minecraft.nbt.NbtElement` |
| `net.minecraft.util.Tuple<A,B>` | нет аналога — своя запись или `com.mojang.datafixers.util.Pair` |
| `Vec3.cross(v)` | `Vec3d.crossProduct(v)` |
| `Vec3.dot(v)` | `Vec3d.dotProduct(v)` |
| `Vec3.normalize()` | `Vec3d.normalize()` |
| `Vec3.x()` / `.y()` / `.z()` | поля `x` / `y` / `z`, либо `getX()` / `getY()` / `getZ()` |

JOML (`Matrix4f`, `Quaterniond`, `Vector3f`) не меняется — он уже на classpath у DRMD.

Имена методов Yarn проверялись по `raw.githubusercontent.com/FabricMC/yarn/1.21.1/mappings/...`, а
не по памяти: `crossProduct` и `dotProduct` — как раз те два, где Mojang и Yarn расходятся, и
угадывание здесь стоит круга через CI.

## Перенесено

### `ImmPtlQuaternions` ← `DQuaternion`

Не второй класс кватерниона, а набор операций над уже существующим `PortalTransform.Quat`. У DRMD
остаётся один тип кватерниона, у вендоренного кода — чистая граница лицензии.

Взято то, чего у DRMD не было: композиция поворотов, построение из оси и угла, восстановление из
ортонормированного репера, сферическая интерполяция, пара «тангаж/рыскание» и снятие накопленной
погрешности. Первые два нужны интегрированию угловой скорости в PHASE 1, третий — чтобы
`ShipAttitude` перестал быть парой векторов forward/up и стал настоящей ориентацией.

Не взято: NBT-сериализация, конверсии в JOML, геттеры (`Quat` — запись), логирование и
`getRotationBetween`.

**Найдена ошибка в комментарии донора.** `matrixToQuaternion` документирован как принимающий три
**строки** матрицы. Код читает `m10` из `y` первого аргумента и `m20` из его `z` — это **столбец**.
Проверено численно: подстановка трёх осей известного поворота восстанавливает этот поворот, а
подстановка транспонированного — нет (расстояние 1.09 против 0). У донора это не всплывало, потому
что его собственные `getAxisW`/`fromFacingVecs` согласованы именно со столбцами. У нас метод
называется `fromBasisImages`, и на несовпадение есть тест.

**Ещё одно, что стоило вендоринга.** `interpolate` переворачивает знак одного из входов при
отрицательном скалярном произведении — кватернион и его отрицание задают один поворот, и без этого
интерполяция идёт длинной дугой и заметно крутит не туда. А `fixFloatingPointErrorAccumulation`
существует потому, что накопленная погрешность у донора ломала телепортацию и коллизию. Первое из
памяти пишется с вероятностью 50%, второе не пришло бы в голову вовсе.

## Что дальше, по убыванию пользы

| Кандидат | Строк | Зачем |
|---|---|---|
| `Plane` | 146 | плоскость и отсечение; зависит только от `Vec3` — самый дешёвый следующий шаг |
| `AARotation` + `IntMatrix3` | 322 | 24 осевые ориентации куба — для панелей и структур |
| `GeometryUtil` | 384 | геометрия боксов и выпуклых оболочек |
| `IntBox` | 540 | целочисленный бокс с обходом — для структур и генерации |

Миксины (134 ядровых) — **не сюда**. Их цена в
[`IMMPTL_STACK.md`](../IMMPTL_STACK.md): 10 из 11 ванильных классов, в которые DRMD уже вмешивается,
одновременно цели ImmPtl, и это система 6DoF-полёта. Это не «добавить файлы», а свести две системы
инъекций в одни и те же методы. 29 рендерных миксинов DRMD обошёл целиком своим путём и переносить
их незачем.
