## Вторая группа: кубические чанки и порталы

Появилась отдельно, под два своих брифа. Ветка по умолчанию указана не для полноты — она решает,
какой код читать, и у половины репозиториев это не `main`.

| Форк | Ветка по умолчанию | Что это | Лицензия |
|---|---|---|---|
| `CubicChunks` | `MC_1.12` | Первая версия, Forge, Minecraft 1.12 | MIT (в шапке каждого файла) |
| `CubicChunks2` | `MC_1.18` | Вторая версия | MIT |
| `CubicChunks3` | `dev` | Третья версия | MIT |
| `FarPlaneTwo` | `dev/abstract-everything` | Дальний рендер для кубических миров | MIT **плюс** требование атрибуции |
| `SeamlessPortals` | **`1.21`** | **Не SeamlessPortals** — порт Immersive Portals под NeoForge | Apache-2.0 |
| `portal_gun` | `main` | Портальная пушка (TarLaboratories) | MIT |
| `portal-gun-mod` | **`1.21.1`** | Портальная пушка (MeowMC) | MIT |

**`portal-gun-mod` собирается под 1.21.1** — версию DRMD, и это единственный донор во всём наборе,
чей код не надо переводить ни через версию игры, ни через загрузчик.

**Имя `SeamlessPortals` вводит в заблуждение.** В репозитории лежит Immersive Portals — все 525
файлов в пакетах `qouteall.imm_ptl.*`, `archives_base_name=immersive-portals`, — портированный под
**NeoForge** (единственный gradle-плагин сборки `net.neoforged.gradle.userdev`, Fabric API через
`org.sinytra.forgified-fabric-api`). DRMD собирается под Fabric, поэтому вставить его нельзя; чем он
всё-таки ценен — в [`portal-engine.md`](portal-engine.md).

**`CubicChunks` — MIT, но узнать это можно только из исходников.** Файла `LICENSE` в корне нет ни
под каким именем; лицензия объявлена в шапке каждого `.java` («This file is part of Cubic Chunks
Mod, licensed under the MIT License (MIT). Copyright (c) 2015-2021 OpenCubicChunks»). Отсутствие
корневого файла — не отсутствие лицензии, и наоборот тоже: у `BlockPhysics` из первой группы нет ни
того, ни другого.

**У `FarPlaneTwo` лицензия не MIT, а «Adapted from MIT».** Первая строка выглядит как MIT, и на этом
разбор кончать нельзя — ровно так я ошибся с Immersive Portals. Полный текст добавляет условие:
использующий обязан указать авторство оригинала (DaPorkchop_) **и дать ссылку на проект**. Копировать
можно, но уведомление сильнее обычного MIT.

Чего в этих группах нет по сравнению с брифами: `CubicWorldGen`,
`ricks-portal-gun-multiloader`, `iPortalTeam/PortalGun`, `ImmersivePortalsModForForge`.

## Чего в форках нет

Три проекта из плана отсутствуют:

- **Create** — донор для §6 (сборка структур). Upstream MIT для кода, ассеты All Rights Reserved.
- **Immersive Portals** — донор для §14. Форка нет, но есть присланный архив исходников 6.0.6 под
  MC 1.21.1, и его бинарник той же версии уже лежит в дереве
  (`libs/immersiveportals-6.0.6-mc1.21.1-fabric.jar`, коммит `b794e6e`). Ветка `1.21` —
  **Apache-2.0**, то есть копировать оттуда можно; см. разбор ошибки в `license-map.md`.
- **RingWorld** — донор для §13 (периодическая топология). Аналога среди форков нет.

## Четыре расхождения, которые меняют план

### 1. Distant Horizons в форках нет

`terminaldetector/distant-horizons` — это репозиторий **готовых LOD-данных** («LOD files of many
popular maps for Distant Horizons alpha 2.1+»), а не исходный код мода. Ни одной строки движка DH.

План опирается на DH в разделах 10, 11 и 12 — иерархический LOD, кэш регионов, бесшовные границы.
Без исходников этот донор выпадает. Upstream живёт на GitLab и лицензирован **GPL-3.0**, то есть
даже с доступом из него нельзя было бы копировать в MIT-проект — только читать как описание.

### 2. Зато есть кое-что лучше — и оно MIT

`voxel-horizon-java-edition` оказался не модом, а **отдельным воксельным движком на Java 21 и
LWJGL**, написанным как раз вокруг стриминга: бесконечные координаты, генерация по регионам,
детерминированность, кэш страниц, «рендер может запросить любой чанк в любой момент». Его README —
буквально архитектурное описание того, что план требует в разделе 11.

И он **MIT**. То есть это единственный донор по стримингу и LOD, из которого разрешено копировать
код. Он занимает место, которое план отводил Distant Horizons, и занимает его на лучших условиях.

Одна оговорка: это не мод, у него нет ни чанков Minecraft, ни его тиков, ни клиент-серверного
разделения. Переносится архитектура, а не интеграция.

### 3. Valkyrien Skies здесь — первая версия, и это выгодно

Форк — `Valkyrien-Skies`, не `Valkyrien-Skies-2`. Первая версия объявлена EOL, живёт на Minecraft
1.12 и лицензирована **Apache-2.0**. Вторая версия — LGPL-3.0.

Обмен получается неожиданно удачным: VS2 современнее, но копировать из него в MIT-проект нельзя;
VS1 старше, зато Apache-2.0 разрешает брать код с указанием авторства. А для PHASE 1 нужен не
современный код, а правильная модель твёрдого тела — масса, тензор инерции, силы, моменты, —
и она за десять лет не изменилась.

Смотреть в VS1 стоит именно на ядро физики, а не на интеграцию с Minecraft 1.12, которая устарела
целиком.

### 4. BitsAndChisels — CC0, то есть без единого условия

Это не Chisels & Bits (MIT, Forge), а мод CoolMineman под Fabric, вдохновлённый им. **CC0-1.0** —
отказ от прав, public domain. Копировать можно что угодно и без атрибуции.

Плюс он делает ровно то, что нужно разделу 8: greedy meshing поверх Fabric Renderer API. Это тот же
рендер-стек, что у DRMD.

Рядом `LittleTiles` даёт 4096 подъячеек на блок против нынешних 64 у `MicroGrid` — прямой ответ на
вопрос масштабирования из §8, но под LGPL-3.0, то есть только как описание.

### 5. BlockPhysics использовать нельзя

Файла лицензии нет; в README вместо неё фраза «Don't be a jerk. Keep things open source. Don't try
to make money off of it». Это не OSI-лицензия и не разрешение в юридическом смысле — по умолчанию
все права сохранены за автором. Ни копировать, ни распространять производное нельзя. Ценность как
донора всё равно близка к нулю: мод 2015 года про падающие блоки, «currently supports downward
movement and sliding».
