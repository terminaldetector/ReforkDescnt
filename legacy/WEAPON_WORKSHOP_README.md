# DRMD 6DOF — Weapon Workshop

## Overview

The **Weapon Workshop** is a full-featured in-game editor for designing, tuning, and exporting 6DOF weapons in Garry's Mod. Built on the **SWEP Construction Kit (SCK)**, it provides four integrated editors — **Stats**, **Projectile**, **Flak**, and **Guidance** — plus a **code generator** that converts your designs into production-ready SWEP Lua files.

The system is **schema-driven** (field definitions drive the UI), **live-tunable** (changes apply in real-time via a config registry), and **fully autonomous** — SCK works standalone without DRMD, and DRMD uses it as an optional external tool.

---

## Architecture

### Three-Layer System

#### 1. **Schema Layer** (`schema.lua`)
Defines field types and structure for all four weapon parameter categories:
- **Weapon** — game mechanics (name, class, category, type, fire rate, damage, energy cost, etc.)
- **Projectile** — physics (model, mass, gravity, drag, lifetime, homing, explosion, trails)
- **Flak** — cassette systems (fragment count, spread, detonation rules, fragment physics)
- **Guidance** — homing/seeking (guidance type, lock time, tracking cone, prediction, target memory)

Each field descriptor includes: type, label, min/max, defaults, and section groupings.

#### 2. **Config Registry** (`config.lua`)
Runtime layer that:
- Stores weapon configurations in memory (`SCK_Config._registry`)
- Persists to disk as glon-encoded files in `DATA/drmd_weapons/<class>.txt`
- Networks changes from client → server → all clients via `net.Send`
- Supports schema extensions (DRMD adds category/ammo type choices at runtime)

#### 3. **UI Renderer** (`ui_schema.lua`)
Generic panel builder that:
- Takes a schema and a data table
- Renders the correct GMod control for each field type:
  - **int/float** → `DNumSlider` with min/max/decimals
  - **string** → `DTextEntry` (single line)
  - **text** → `DTextEntry` (multi-line)
  - **bool** → `DCheckBoxLabel`
  - **enum** → `DComboBox` with choices (+ dynamic extensions)
- Groups fields by section headers
- Calls `onChange` on every edit (for live sync and registry persistence)

**Result:** One renderer function powers all four editor tabs.

## Editor Tabs

### **Stats** (Weapon Parameters)
Edit core weapon mechanics:
- PrintName, ClassName, Category, WeaponType
- AmmoType, MaxAmmo
- FireRate, Cooldown
- Damage, SplashRadius
- EnergyCost
- Weight, AIPriority

**Plus preset bar:**
- **Save / Load / Clone** — persist complete configs
- **Template** — quick-start configs (Cannon, Missile, Flak, Seeker)
- **Copy SWEP Lua** — generate code to clipboard
- **Write SWEP file** — save to `DATA/drmd_weapons/generated/`

### **Projectile**
Configure what fires:
- Model, Scale, Mass
- Physics: Gravity, Drag, Lifetime, Velocity, Acceleration
- Homing: enable + turn rate
- Explosion: radius, damage
- FX: trail, light, impact effect
- Penetration: ricochet, pierce count
- Clustering: fragment count, spread, delay, submunition entity

### **Flak**
Design cassette/burst systems:
- FragmentCount, SpreadAngle, Randomness
- FragmentType (kinetic/explosive/energy/exotic)
- FragmentSpeed, Size, Damage
- DetonateTime, DetonateDistance

### **Guidance**
Set up homing/seeking:
- GuidanceType (none/heat/target/beam/lead)
- HeatSeeking, TargetSeeking, BeamRiding toggles
- LockTime, TrackingCone, MaxAngularVelocity
- LeadPrediction, PredictionStrength
- TargetMemory, LostTargetTimeout

## Code Generation

The **generator** (`generator.lua`) emits a complete, valid SWEP Lua file from a config:

```lua
-- Generated by DRMD Weapon Workshop (SCK)
-- Class: weapon_d6_custom
-- DO NOT EDIT — regenerate via SCK editor.

AddCSLuaFile()

SWEP.PrintName = "Custom Weapon"
SWEP.Category = "Primary"
SWEP.Spawnable = true
-- ... metadata ...

local ENERGY_COST = 10
local FIRE_RATE = 0.5
local DIRECT_DMG = 50
-- ... more constants ...

function SWEP:Initialize()
    self:SetWeaponHoldType(self.HoldType)
end

function SWEP:PrimaryAttack()
    -- ... energy check, D6_Wep.FireProjectile call with config.projectile params ...
end

-- HUD, SecondaryAttack, SetupDataTables stubs
```

**Features:**
- Calls `D6_Wep.FireProjectile` with projectile parameters
- `onHit` callback with `DirectDamage` + `SplashDamage`
- Flak burst loop (if FragmentCount > 0)
- Auto-detects hitscan vs. projectile based on WeaponType
- Includes WeaponClusters block (if present)
- Comments opt-in path for `D6_Wep.Cfg()` live tuning

**Output:**
- Clipboard (paste immediately)
- `DATA/drmd_weapons/generated/<class>.lua`

## Persistence

All four editor states are saved to a **preset**:
```lua
save_data = {
    -- existing SCK fields
    v_models, w_models, v_bonemods,
    ViewModel, CurWorldModel, ViewModelFOV,
    HoldType, ViewModelFlip, IronSights...,
    clusters,  -- from Clusters tab
    
    -- NEW: weapon config (all 4 sections)
    weaponconfig = {
        weapon = {...},
        projectile = {...},
        flak = {...},
        guidance = {...}
    }
}
```

Presets are glon-encoded to `DATA/swep_construction_kit/<name>.txt`. Load any preset and all four editors are restored.

## Independence & DRMD Integration

### SCK Standalone
The SWEP Construction Kit addon **requires zero DRMD dependencies**:
- Schemas are generic (no DRMD-specific terms)
- Config registry is self-contained
- Generator emits valid SWEPs that call `D6_Wep.*` only if available
- All editor logic is local to SCK

**Run SCK without DRMD?** Full editor works. Presets save/load. Code generation works. You just don't get DRMD enum extensions.

### DRMD Opt-In Shim (`d6_wep_cfg.lua`)
One file in `descent_scanner/lua/autorun/`:

```lua
function D6_Wep.Cfg(class, section, key, default)
    if not SCK_Config then return default end
    local cfg = SCK_Config.Get(class)
    if not cfg then return default end
    return cfg[section][key] or default
end
```

**Purpose:** Existing weapons (which hardcode stats as file-scope locals) remain untouched. Future weapons can call `D6_Wep.Cfg(...)` to read from the live registry instead. When SCK is absent, returns default with zero overhead.

**Schema extensions** (CLIENT):
```lua
SCK_Config.RegisterSchemaExtension("weapon", "Category", {
    "Anti-Fighter", "Anti-Capital", "Siege",
})
SCK_Config.RegisterSchemaExtension("weapon", "AmmoType", {
    "gravitic", "dark_energy",
})
```

These run at `InitPostEntity` and patch the live schema if it's already loaded.

## Usage Flow

### Designing a Weapon

1. **Equip SCK** → Slot 6 (or spawn with `give swep_construction_kit`)
2. **Primary/Secondary fire** → Opens the editor menu
3. **Go to Stats tab** → Set weapon name, type, fire rate, damage, energy
4. **Go to Projectile tab** → Set model, mass, lifetime, velocity, trail, homing
5. **Go to Flak tab** (optional) → Set fragment burst on impact
6. **Go to Guidance tab** (optional) → Set homing parameters
7. **Go to Clusters tab** → Add weapon parts (barrel, launcher, etc.)
8. **Stats tab → "Copy SWEP Lua"** → Paste into your weapon file or save to disk
9. **"Save" preset** → Name it and persist all 4 editor states

### Migrating an Existing Weapon

Old weapon hardcodes stats:
```lua
local ENERGY_COST = 20
local FIRE_RATE = 0.8
local DIRECT_DMG = 80
```

Migrate to live-tunable:
```lua
local ENERGY_COST = D6_Wep.Cfg("weapon_d6_custom", "weapon", "EnergyCost", 20)
local FIRE_RATE = D6_Wep.Cfg("weapon_d6_custom", "weapon", "FireRate", 0.8)
local DIRECT_DMG = D6_Wep.Cfg("weapon_d6_custom", "weapon", "Damage", 80)
```

(Or leave as-is — old weapons continue to work unchanged; opt-in is per-weapon.)

## Key Design Decisions

1. **Schema-driven, not hard-wired**
   - One renderer function (`SCK_BuildSchemaPanel`) powers all four tabs
   - Schemas are data (lists of field descriptors)
   - Easy to extend or modify without touching UI code

2. **Live registry, not file-only**
   - Config changes persist to disk AND sync to all clients
   - Changes apply immediately (no reload needed)
   - Past weapons untouched (no forced migration)

3. **Autonomous SCK, optional DRMD**
   - SCK works standalone (generates valid SWEPs)
   - DRMD adds enum choices and the `Cfg()` shim
   - One-way dependency: DRMD → SCK; SCK ↛ DRMD

4. **Code generation, not just config**
   - Generator emits complete, valid Lua (not just constants)
   - Output is `D6_Wep` framework-aware (calls FireProjectile with config params)
   - Can write to disk or clipboard for quick iteration

## Verification Checklist

✅ **Editor renders from schema:**
   - Open SCK → Stats/Projectile/Flak/Guidance tabs visible
   - Each field renders the correct control (slider/text/combo/checkbox)
   - Section headers group fields correctly

✅ **Live registry:**
   - Change Damage slider → registry updates in real-time
   - Close and reopen menu → value persists
   - Value syncs to server (print on receive)

✅ **Generation:**
   - Click "Copy SWEP Lua" → paste into file
   - `luajit -bl` parses clean
   - Spawn weapon → fires projectile with configured speed/damage/scale

✅ **Presets:**
   - Save → Load round-trips full config
   - Clone duplicates with new name
   - Template loads starter (Cannon/Missile/Flak/Seeker)

✅ **Independence:**
   - Remove DRMD addon → SCK editor still works, generation works, presets work
   - Remove SCK addon → DRMD loads with no errors; `D6_Wep.Cfg()` returns defaults

✅ **No regressions:**
   - Existing weapons fire unchanged (don't call registry yet)
   - SCK visual/cluster editors still work
   - Base render pipeline (ViewModelDrawn, etc.) untouched

## Contributing

The workshop system is modular and extensible:

- **Add a schema field?** Edit `schema.lua`, it auto-renders via `SCK_BuildSchemaPanel`
- **Add a control type?** Add a case to `ui_schema.lua`
- **Add DRMD enum choices?** Call `SCK_Config.RegisterSchemaExtension()` from `d6_wep_cfg.lua`
- **Extend the generator?** Add logic to `BuildSWEPString()` in `generator.lua`

All code is namespaced as `SCK_*` (public API) or file-local. Zero globals.
