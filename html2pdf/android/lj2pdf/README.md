# LJ → PDF book (Android)

Нативное Android-приложение: скачивает блог **LiveJournal** постранично и
собирает из него **единый `book.pdf` с кликабельным оглавлением** — мобильный
аналог десктопного `httrack2pdf`.

В отличие от десктопной версии здесь **не нужны** ни Chrome, ни Ghostscript:
* рендер каждой страницы в PDF делает встроенный системный `WebView`
  (рисуется прямо на `PdfDocument`, с разбивкой длинных страниц на A4);
* склейку и оглавление — библиотека **PDFBox-Android** (`PDFMergerUtility`
  + `PDDocumentOutline`, кириллица в закладках поддерживается).

Интерфейс на **Material 3**. Конвертация идёт в **фоновом сервисе** с
уведомлением-прогрессом — приложение можно свернуть; по готовности тап по
уведомлению открывает книгу.

## Главный сценарий: «поставил на ночь — утром книга»

Как у torrent-архиватора. Для **LiveJournal**:

1. **Скан.** Приложение читает **архив-календарь** (`/calendar` → `/ГГГГ/ММ/`,
   при необходимости по дням) и собирает **полный** список постов всего блога
   (пермалинки `…/<id>.html`). Важно: обычная пагинация `?skip=` у LJ обрезается,
   поэтому для больших блогов (сотни страниц) полный охват даёт именно календарь;
   если календаря нет — откат на `?skip=`.
2. **Выбор объёма.** Показывает «Найдено N постов» и даёт выбрать, сколько
   сохранить, **начиная со свежих**: всё / половина / треть / своё число.
   *(Либо галка «Download everything automatically» — без вопросов, сразу всё:
   включил, убрал телефон, утром готовый PDF.)*
3. **Скачивание + сшивка.** Каждый выбранный пост открывается **целиком — с
   комментариями и медиа**, чистится от рекламы, рендерится в PDF; в конце —
   единый `book.pdf` с оглавлением по постам.

Долгие ночные прогоны держит **wake-lock** (работает с погашенным экраном) и
foreground-сервис; всё под уведомлением-прогрессом.

> **Важно для фона:** при первом запуске приложение попросит разрешение
> **«Поверх других приложений»**. Оно нужно, чтобы рендер шёл и при свёрнутом
> приложении — иначе WebView без видимого окна перестаёт рисовать и прогресс
> «замирает/сбрасывается». Без разрешения работает только пока окно открыто.

### Память (фазовая обработка)

Память держится низкой по фазам: **скан** хранит только ссылки; **рендер** идёт
по одному посту → сразу пишется в `posts/<id>.pdf` и освобождается, а WebView
**пересоздаётся каждые 8 страниц**; **склейка** PDFBox идёт через временные
файлы. Пиковая память ≈ один WebView + один PDF, а не весь блог сразу.

## Проекты и обновление

Каждый заархивированный блог сохраняется как **проект** (папка
`…/files/projects/<host>/` с отдельными PDF на каждый пост, индексом и
`book.pdf`). Кнопка **«Projects»** показывает список сохранённых блогов.

**Обновление** (как «дозакачка торрента»): в проекте появилось, скажем, 10
новых статей — жмёшь **Projects → блог → Update**. Приложение сканирует только
**верх** ленты до первого уже сохранённого поста, докачивает **только новые**
статьи и **пересобирает** `book.pdf` (старые посты не рендерятся заново — берутся
готовые PDF). Если новых нет — «already up to date».

Повторный **Start** на том же блоге делает то же самое (создаёт проект на первый
раз, дальше — обновляет).

## RAG-экспорт (база для локальных нейросетей)

Из скачанных проектов можно собрать **корпус для RAG** прямо на телефоне:
текст извлекается **из готовых PDF** (PDFBox), режется на чанки и пишется в
**JSONL** — по записи на чанк: `{source, id, title, url, chunk, text}`.

- **Projects → проект → Export RAG (JSONL)** — один проект.
- **Projects → Merge → RAG** — объединить все проекты в один корпус.

Телефон отдаёт датасет (`*_rag.jsonl`) в выбранную папку / через «Поделиться»;
**эмбеддинги/векторную БД строит уже локальная сторона** (LangChain, llama-index,
Ollama, LM Studio — все едят JSONL). Так локальная модель получает знания блога
для дообучения/поиска. Размер чанка ~1000 симв., перекрытие ~150.

## Платформы (профили)

Движок (рендер → PDF → оглавление, проекты, обновление, фон) общий, а
перечисление статей задаёт **профиль сайта**, выбираемый автоматически по URL:

| Профиль | Сайты | Перечисление |
|---------|-------|--------------|
| LiveJournal | `*.livejournal.com` | архив по годам/месяцам (+ backdated 1940+) |
| Habr | `habr.com` | страницы постов автора `/posts/pageN/` |
| **Facebook** | `facebook.com`, `m.` / `mbasic.` / `web.`, `fb.com` | лента `mbasic` по ссылкам «показать ещё» (нужен вход) |
| Generic | прочие (напр. Sefaria) | сбор ссылок со страницы-оглавления |

Режим **«Blog / site archive»** + галка **Full posts** работает для всех:
вставь URL — платформа определится сама. Профили DTF/TJournal (osnova API) и
специализированный **дампер форумов** — в планах (под них уже есть точка
расширения `SiteProfile`).

## Facebook — вход как браузер, без API и приложения

Facebook показывает стену только вошедшему пользователю и не даёт открытого API
для выгрузки. Поэтому авторизация здесь **браузерная**: приложение **не
регистрируется** в Facebook, не просит токенов и ключей — оно один раз открывает
настоящую страницу входа в `WebView`, а дальше пользуется теми же cookie, что и
браузер.

1. Кнопка **FB** в шапке → **Войти**. Откроется обычная страница Facebook. Логин,
   пароль и двухфакторка вводятся **в её собственную форму** — приложение их не
   видит: они уходят прямо в Facebook по TLS.
2. Как только Facebook выдаёт сессию (cookie `c_user`), окно закрывается само.
3. Вставьте в поле URL ссылку на страницу, профиль или группу и нажмите **Start** —
   дальше всё как с любым блогом: скан → выбор объёма → скачивание → PDF / EPUB /
   RAG, обновление «докачать новые».

Что именно происходит под капотом:

* читается **`mbasic.facebook.com`** — версия сайта без JavaScript: обычный HTML с
  настоящими `<a href>`, который штатный конвейер (OkHttp + jsoup) разбирает так же,
  как ленту LiveJournal;
* перечисление идёт по **собственным ссылкам «показать ещё»** ленты, а не по
  угаданным форматам курсоров, поэтому переживает смену внутренних параметров;
* каждый запрос несёт cookie **и тот же `User-Agent`**, что и окно входа
  (`BrowserSession`), — Facebook видит один и тот же клиент, а не сессию, сменившую
  браузер на полпути;
* пост опознаётся по числовому `story_fbid`, поэтому один и тот же пост, найденный
  как `story.php`, `permalink.php` или `/posts/<id>`, — это **один** файл в архиве,
  и «Обновить» его не перекачивает;
* каждая страница/группа — **отдельный проект** (`facebook.com_<кто>`), архивы не
  смешиваются;
* соединений к Facebook — не больше двух, между страницами ленты пауза ~1 с: иначе
  Facebook быстро отвечает капчей вместо контента.

**Выйти** — та же кнопка **FB → Выйти**: cookie стираются, ничего от сессии не
остаётся. Сессия хранится только в cookie-хранилище WebView (приватная папка
приложения); приложение её никуда не копирует и не передаёт.

**Ограничения.** Сохраняется страница поста целиком, как её отдаёт mbasic: текст,
фото и первые комментарии. Полная ветка комментариев (кнопка «показать ещё
комментарии»), видео и «Истории» не выгружаются. Facebook может потребовать
повторный вход или проверку — тогда в логе будет `[fb] not signed in` или
`Facebook login page`, и нужно снова нажать **FB → Войти**. Архивируйте то, к чему
у вас есть доступ: автоматический сбор чужих данных нарушает правила Facebook, и
ответственность за это на вас.

### Режимы
* **Full posts (with comments & media)** — качать страницы постов целиком
  (рекомендуется для архива). Если снять — берутся страницы-ленты `?skip=` (без
  комментариев, быстрее, но обрезанные превью).
* **Сайт с шаблоном** — произвольный URL с `{n}` + диапазон.
* **Одна страница** — один URL → один PDF.

**Без рекламы:** галка **«Remove ads / clean»** (вкл. по умолчанию) перед
рендером вычищает баннеры/промо (adsbygoogle, adfox/Яндекс, LJ-промо). Эвристика —
на разных темах LJ результат может отличаться.

Пример для теста: `https://technolirik.livejournal.com/` → режим LiveJournal,
**Full posts** вкл. → Start → скан → выбираешь объём → книга собирается в фоне.

## Куда сохраняется

По умолчанию — в приватную папку приложения; открывается кнопкой **Open PDF**.
Кнопкой **Folder** можно выбрать **свою папку** (системный выбор, SAF) —
готовый `book.pdf` дополнительно копируется туда (доступ запоминается).

## Как пользоваться

1. Выберите режим.
2. Введите URL (и при необходимости диапазон страниц).
3. *(необязательно)* **Folder** — выбрать папку для итогового PDF.
4. **Start** → конвертация идёт в фоне (смотрите уведомление).
5. **Open PDF** или тап по уведомлению — открыть готовую книгу.

## Сборка (Android Studio)

1. `File → Open…` и выберите папку `android_lj2pdf/`.
2. Дождитесь Gradle sync (нужен JDK 17 — встроен в свежие Android Studio).
3. **Build → Build APK(s)** или Run на устройстве/эмуляторе.
   APK появится в `app/build/outputs/apk/`.

> Командная строка `./gradlew assembleDebug` тоже работает, но в репозитории
> нет бинарного `gradle/wrapper/gradle-wrapper.jar`. Android Studio подставит
> свой Gradle автоматически; для CLI один раз выполните `gradle wrapper`
> (установленным Gradle 8.x), чтобы сгенерировать wrapper.

Параметры: `compileSdk 34`, `minSdk 21`, Kotlin 1.9, AGP 8.1.

## Структура

| Файл | Назначение |
|------|-----------|
| `MainActivity.kt` | Material-UI: выбор режима, параметры, выбор папки, запуск |
| `ConvertService.kt` | **фоновый** foreground-сервис: гонит конвейер + уведомления |
| `ConvertBus.kt` | связь сервис ↔ активность (прогресс/лог/результат) |
| `WebViewPdfRenderer.kt` | `WebView` → `PdfDocument` (рендер страницы в PDF) |
| `BookBuilder.kt` | слияние PDF + оглавление (PDFBox-Android) |
| `Facebook.kt` | профиль Facebook: mbasic, перечисление ленты, id постов |
| `BrowserSession.kt` | cookie/UA вошедшего браузера для загрузчика |
| `FacebookLoginActivity.kt` | окно входа (настоящая страница Facebook) |

## Ограничения

* Печатается **полная** страница LJ (как в браузере, с комментариями) —
  HTML-очистка от рекламы из C-версии здесь пока не применяется.
* Авторизация есть только для Facebook (браузерный вход, см. выше). Для приватных
  записей других платформ — пока нет.
* Проверяйте `Entries/page`: если в блоге настроено иное число записей на
  страницу, подгоните его, иначе пагинация `?skip=` сдвинется.
