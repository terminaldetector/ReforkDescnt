# Facebook: вход как браузер, а не как приложение

Facebook не даёт открытого API для выгрузки чужой (да и своей) ленты, а стену
показывает только вошедшему пользователю. Регистрировать приложение, просить
review у Meta и хранить токены ради «скачать свой архив» — путь длинный и
хрупкий: разрешения отзываются, приложение модерируется, API меняется.

Поэтому здесь выбран другой путь: **программа авторизуется так же, как браузер.**
Пользователь один раз входит в настоящей странице Facebook, а дальше архиватор
пользуется теми же cookie сессии. Никакого `app_id`, никаких ключей.

---

## Как это сделано в двух частях проекта

| | Android (`android/lj2pdf`) | ПК (`pc/httrack_pdf_mod`) |
|---|---|---|
| Где открывается вход | `WebView` внутри приложения (`FacebookLoginActivity`) | обычное окно Chrome/Edge (`--login`) |
| Где живёт сессия | cookie-хранилище WebView, приватная папка приложения | папка профиля браузера, которую задал пользователь |
| Кто её использует | загрузчик OkHttp через `BrowserSession` | тот же браузер при печати, с `profile=<папка>` |
| Что читается | `mbasic.facebook.com` (HTML без JS) | то, что уже скачано зеркалом / отдано по URL |
| Как выйти | **FB → Выйти** (cookie стираются) | удалить папку профиля |

Общее в обоих случаях: **пароль вводится в форму самого Facebook**, а не в поле
нашей программы. Он уходит прямо в Facebook по TLS; программа его не видит, не
логирует и не хранит. Двухфакторная аутентификация и проверки безопасности
работают ровно потому, что это настоящий браузер.

## Android: шаг за шагом

1. Кнопка **FB** в шапке → **Войти**. Открывается `mbasic.facebook.com/login/`.
2. Вход (в том числе 2FA). Как только Facebook ставит cookie `c_user` — признак
   выданной сессии — окно закрывается само.
3. В поле URL — ссылка на профиль, страницу или группу, например:
   * `https://www.facebook.com/zuck`
   * `https://www.facebook.com/profile.php?id=100044…`
   * `https://www.facebook.com/groups/123456`
   * либо прямая ссылка на один пост.
4. **Start** — дальше всё как с любым блогом: скан → «сколько сохранить» →
   скачивание HTML-базы → **PDF / EPUB / RAG**, а позже «Обновить (докачать
   новые)».

### Что происходит внутри

**Читается mbasic.** `mbasic.facebook.com` — версия сайта без JavaScript,
обычный HTML с настоящими `<a href>`. Штатный конвейер архиватора (OkHttp +
jsoup) разбирает её так же, как ленту LiveJournal, — отдельного «движка
Facebook» не понадобилось.

**Перечисление по собственным ссылкам ленты.** Курсоры пагинации у Facebook
недокументированы и меняются (`sectionLoadingID`, `unitcursor`, `bacr`, …).
Поэтому следующая страница не конструируется, а **берётся со страницы**: любая
ссылка, которую mbasic сам предлагает как продолжение («See more stories»,
«Показать ещё»). Смена внутреннего формата курсора это переживает.

**Один пост — один файл.** Facebook ведёт к одной записи несколькими путями:
`story.php?story_fbid=…`, `permalink.php?story_fbid=…`, `/<user>/posts/<id>`,
`/groups/<gid>/permalink/<id>/`. Идентификатором взят числовой `story_fbid`,
поэтому все они складываются в один `fb<id>` — дубликатов в книге нет, а
«Обновить» узнаёт уже скачанное и останавливается на нём.

**Каждая цель — отдельный проект.** Обычно проект = хост, но у Facebook все
стены живут на одном хосте. Поэтому имя проекта включает саму цель:
`facebook.com_zuck`, `facebook.com_group_123456`, `facebook.com_id_100044`.
Два архива не сольются в один.

**Одна и та же личность на всех запросах.** `BrowserSession` отдаёт загрузчику
не только cookie, но и **тот же `User-Agent`**, что был у окна входа, плюс
`Accept-Language` и `Referer`. Facebook видит один клиент, а не сессию, сменившую
браузер на полпути.

**Вежливый темп.** Соединений к Facebook — не больше двух (что бы ни стояло в
«профиле скорости»), между страницами ленты пауза ~0.8–1.5 с. Facebook быстро
отвечает капчей на жадного клиента, и медленный скан лучше, чем заблокированная
сессия.

**Понятная диагностика.** Если сессии нет или она протухла, mbasic отдаёт форму
входа вместо ленты. Это распознаётся, и в лог идёт `[fb] not signed in …` или
`Facebook login page (session expired?)` — вместо молчаливых «найдено 0 постов».

## ПК: шаг за шагом

`httrack2pdf` печатает страницы настоящим headless-браузером, поэтому «войти как
браузер» здесь буквально: браузеру даётся **постоянный профиль**, в который
пользователь один раз вошёл руками.

```bash
# 1) один раз — откроется обычное окно, войдите и закройте его
./httrack2pdf --login ~/.httrack2pdf-fb https://www.facebook.com/

# 2) дальше печатайте этим профилем
./httrack2pdf /path/to/mirror "export,merge,profile=$HOME/.httrack2pdf-fb"
```

Ограничение: Chrome не открывает одну папку профиля двумя процессами, поэтому с
`profile=` параллелизм автоматически становится `1`. Для `--login` нужен полный
Chrome/Edge — у `chrome-headless-shell` окна нет, и программа скажет об этом
вместо того, чтобы молча ничего не открыть.

## Изображения: оригиналы, а не превью

Для картиночных страниц это главное. mbasic **никогда** не отдаёт оригинал в
самой записи: `<img>` — это превью (`/s320x320/…`), завёрнутое в ссылку на
страницу фотографии. Размер зашит в подписанный CDN-URL, поэтому переписать его
руками нельзя — подпись перестанет сходиться. Настоящий файл лежит на один
переход дальше, за ссылкой «Открыть оригинал» (`/photo/view_full_size/?fbid=…`),
и архиватор этот переход делает — см. `Facebook.fullSizeImage`.

Режим **«Только изображения»** (галка на главном экране) строится на этом:

* фотографии берутся в полном размере — и те, что показаны превью в записи, и те,
  что в записи только ссылкой («Ещё N фото»);
* интерфейс Facebook не путается с содержимым: спрайты и эмодзи живут на
  `static.xx.fbcdn.net/rsrc.php/…` и отбрасываются **по URL, без скачивания**;
  аватарка же лежит на том же контентном CDN, что и фотографии, и отличить её
  можно только по размеру — поэтому она скачивается и отсеивается порогом;
* одно и то же фото в ленте, в записи и в альбоме сохраняется **один раз** —
  сравнение по содержимому, а не по ссылке;
* повторный запуск докачивает только новое.

На выходе — папка с оригиналами, индекс и альбом **CBZ** (файлы как есть) и/или
**PDF** (по картинке на страницу, страница по пропорциям картинки, закладки).

Цена: **лишний запрос на каждую картинку**. При двух соединениях и паузе между
страницами большой фотоальбом — это ночной прогон. Полный размер можно выключить
в ⋮ → «Настройки изображений», тогда сохранятся превью.

## Границы применимости

* Сохраняется страница поста так, как её отдаёт mbasic: **текст, фотографии и
  первые комментарии**. Полная ветка («показать ещё комментарии»), видео,
  «Истории» и Reels — нет.
* В режиме изображений берутся фотографии; видео и анимации из Reels — нет.
  Фото из комментариев попадут только если mbasic показал их на странице.
* Лента ограничена тем, что показывает mbasic: если Facebook перестанет его
  отдавать вашему аккаунту, перечисление остановится (это будет видно в логе).
* Скан большой стены — небыстрый: две связи и пауза между страницами.
* Facebook может в любой момент потребовать повторный вход или проверку. Это
  штатная ситуация: **FB → Войти** ещё раз, скачанное не теряется — «Обновить»
  докачает остальное.

## Об ответственности

Инструмент рассчитан на **личный архив: то, к чему у вас есть доступ** — своя
стена, свои группы, страницы, которые вы ведёте. Автоматизированный сбор данных
Facebook в общем случае противоречит его правилам, а выгрузка чужих персональных
данных может нарушать закон о персональных данных. Ответственность за то, что и
откуда вы выгружаете, лежит на вас.

Сессия хранится только у вас: в cookie-хранилище приложения (Android) или в
папке профиля браузера (ПК). Ни программа, ни этот проект её никуда не
отправляют. «Выйти» стирает её.

## Где что лежит

| Файл | Роль |
|------|------|
| `android/lj2pdf/…/Facebook.kt` | профиль платформы: mbasic-URL, id постов, обход ленты, отбор содержимого |
| `android/lj2pdf/…/BrowserSession.kt` | cookie + `User-Agent` вошедшего браузера для OkHttp |
| `android/lj2pdf/…/FacebookLoginActivity.kt` | окно входа (настоящая страница Facebook) |
| `android/lj2pdf/…/Http.kt` | `Http.Identity` — точка, куда подключается сессия |
| `android/lj2pdf/…/SiteScan.kt`, `SiteProfile.kt` | маршрутизация facebook-ссылок в профиль |
| `android/lj2pdf/…/HtmlArchiver.kt` | извлечение текста поста из mbasic-разметки |
| `android/lj2pdf/…/ImageArchiver.kt` | режим «только изображения»: оригиналы, фильтры, дедуп |
| `android/lj2pdf/…/AlbumBuilder.kt` | галерея → альбом PDF / CBZ |
| `pc/httrack_pdf_mod/httrack_pdf.c` | `profile=<dir>`, `--login`, ограничение параллелизма |

Точка расширения общая: другая платформа с браузерным входом добавляется так же —
свой `SiteProfile` + `Http.Identity` для своих хостов.

Проверки на всё перечисленное (плюс выгрузка содержимого и сборка PDF/EPUB/RAG)
лежат в [`tools/jvm-checks`](../tools/jvm-checks/README.md) и гоняются в CI:
они компилируют настоящие файлы приложения, а не их копии.
