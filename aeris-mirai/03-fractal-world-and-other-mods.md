# 3 (продолжение). Fractal World и другой 3D-worldgen под Fabric 1.21.x

Вторая половина раздела 3 брифа. Основано на исследовании фоновым агентом — GitHub (исходники читались
напрямую) плюс сниппеты WebSearch там, где сама страница была недоступна (`modrinth.com`,
`curseforge.com`, `youtube.com`, `web.archive.org` — все заблокированы прокси этой среды; ещё одно
независимое подтверждение того же ограничения, что уже описано в README).

## "Fractal World" — два разных кандидата, ни один не бьёт точно в цель брифа

Агент прямо предупреждает: не уверен, какой из них имелся в виду изначально — оба реальны, оба
называются похоже, оба непохожи на то, что нужно.

**Кандидат A — "Fractal World" на Modrinth** (`modrinth.com/mod/fractal-world`, id `jul4eHIp`). Публичного
исходника не найдено, страница сама недоступна — вывод собран из многократно повторяющегося в разных
сниппетах текста описания, дословно: *"формула фрактала определяет высоту мира или его цвет... и
сдвигает всю колонку мира вверх или вниз"*. `[НИЗКАЯ УВЕРЕННОСТЬ]` Если это точное описание механизма —
это **сдвиг готовой колонки/варп хайтмапа**, не поблочное решение solid/air по (X,Y,Z). "3D-фрактал" в
настройках, скорее всего, выбирает трёхвходовую формулу для вычисления того же одного скаляра на
колонку, а не даёт независимый результат на каждый воксель. Если это так — несмотря на название, эта
модификация **не решает** и даже не пытается решить задачу "Y как независимая ось", ровно тот подвох, о
котором предупреждает сам бриф. Fabric-only, версии примерно 1.20.1–1.21.4, точная поддержка 1.21.1 не
подтверждена.

**Кандидат B — "Fractal" от Bahnschrift** (`github.com/Bahnschrift/fractal`, MIT) — прочитан агентом
напрямую, высокая уверенность. Это **не генератор мира**, а одноразовая команда (`/fractal mandelbulb`,
`/fractal mandelbox`), архитектурно то же самое, что кисть WorldEdit — заполняет прямоугольную область,
никогда не подключается к конвейеру генерации. Зато сама математика — честный 3D-фрактал: Mandelbulb
(итерация 5-й степени, циклически симметричная по x/y/z, до 100 итераций, выход по magnitude ≥ 4096) и
Mandelbox (fold в [-1,1] по каждой оси + sphere-fold). **Ключевая находка**: на уровне математики Y
абсолютно симметричен X/Z — та же формула нормализации, та же роль в обеих фракталах. Но на уровне
движка — нет: команда требует, чтобы чанки были уже загружены, а единственная версия MC, под которую
это когда-либо собиралось (1.17.1, Forge, **не Fabric**), имела ванильный диапазон высот 0–256 (до
Caves & Cliffs Part II), тогда как X/Z ограничены только границей мира. То есть **сама по себе
формула не видит разницы между осями, а инженерные рамки вокруг неё — видят**, ровно то расслоение,
которое бриф просит задокументировать отдельно для каждого узла.

Отброшенные тёзки (не совпадают по содержанию, отмечены агентом явно): `fractal-lib` (библиотека UI
инвентаря, ничего общего), "Fractal Block World"/"Fractal Block Craft" (мод по мотивам другой игры, не
процедурная генерация), `Fractal_World_Playground` (автономный Java-прототип шумогенерации вне
Minecraft, не завершён), `fractal-datapack` (строит фигуры Серпинского/Мандельброта как **структуры**,
не как рельеф).

## Обзор живого Fabric 1.21.x worldgen-экосистемы

### Расширенные функции плотности (инфраструктура на уровне Java)

**More Density Functions** (klinbee, MIT, Fabric/Forge/NeoForge, **подтверждено 1.21.1**) —
добавляет новые `DensityFunction`-реализации в Java (namespace `moredfs`), доступные из обычного
datapack JSON: координатные градиенты, тригонометрические функции. Это настоящее расширение словаря
`NoiseRouter` на уровне кода, не просто перекомпоновка существующих узлов. `[СРЕДНЯЯ УВЕРЕННОСТЬ]` по
точному каталогу функций (агент не прочитал исходник целиком, только сниппеты релиза/вики) — стоит
свериться напрямую, есть ли Y-градиентная функция наравне с X/Z-градиентными.

**Lithostitched** (Fabric+NeoForge, **подтверждено 1.21.1**) — библиотека совместимости для сшивания
правок рельефа от нескольких модов; зависимость Terralith ниже.

### Перекомпоновка существующего графа плотности (datapack-уровень, без своего ChunkGenerator)

**Terralith** (`Stardust-Labs-MC/Terralith`, Fabric+Forge+NeoForge+Quilt) — ~95 биомов + макрорельеф
(каньоны, парящие острова, впадины). Архитектурно подтверждено: **чисто datapack**, перенастраивает
существующий ванильный граф `data/minecraft/worldgen/density_function/overworld` (например,
`xz_scale`), без единой строчки кастомного Java-генератора.

**Tectonic** (Apollounknowndev, Fabric, **подтверждено 1.21.1**) — крупные когерентные "континенты",
подземные реки. В отличие от Terralith, репозиторий содержит настоящий Java-слой поверх
datapack-ресурсов — добавляет ли этот слой новые типы `DensityFunction` или что-то более структурное,
агент не смог подтвердить (доступны были только метаданные репозитория, не тело README).

**Nullscape** (Fabric+Forge, **"Mod 1.21.x"**) — тот же технический приём Terralith, применённый к
**Энду**: поднимает используемую высоту Энда до 384 блоков, "разбитые острова, парящие долины,
кристаллизованные пики" — тем же инструментарием функций плотности 1.18+. Конкретный, живой пример
ванильной F(X,Y,Z)-системы, реально дающей парящий/несвязный рельеф в неосновном измерении.

### Хайтмап + эрозия — включено как контрпример, НЕ объёмная генерация

**TerraForged → ReTerraForged** (racoonman2, Fabric+Forge, **до 1.21.x не доехал** — прямая проверка
`git ls-remote` агентом: ветки только 1.19.4/1.20.1/1.20.2, ни одной 1.21). Механизм подтверждён по
исходнику: **Mixin в `NoiseBasedChunkGenerator`** (`MixinNoiseBasedChunkGenerator.java`), классический
2D-хайтмап с симулированной гидравлической эрозией и реками по накоплению стока — то есть буквально
F(X,Z)→высота, просто хайтмап гораздо более высокого качества, чем ванильный. Полезно именно как
негативный пример: даже мод, знаменитый "реалистичностью" рельефа, под капотом остаётся плоским.

**TerraScribe** (Sammasr, NeoForge-only, 1.21.1, **до-альфа**) — заявленный духовный преемник
ReTerraForged, тот же приём. Упомянут только потому что маячит на горизонте: не Fabric, не готов.

### Пещеры как основной/заменяющий элемент генерации — самая полезная живая находка этого раздела

**YUNG's Better Caves** (YUNGNICKYOUNG, LGPL-3.0, Fabric+NeoForge, **подтверждено 1.21–1.21.1**,
отдельная ветка `1.21.1` в репозитории) — прочитан агентом напрямую по исходнику, высокая уверенность.
Это **самый близкий к цели брифа живой, работающий, версионно-актуальный прецедент** из всего
исследования:

- Архитектурно — кастомный **`WorldCarver`** (`BetterCavesWorldCarver`), подключается в существующую
  ванильную точку расширения для вырезания пещер, не заменяет `ChunkGenerator` целиком и не трогает
  граф плотности напрямую.
- Форма пещер — честная 3D-шумовая функция, вызываемая прямо на (x,y,z):
  `NoiseGen.generateNoiseColumn()` → `noise.GetNoise(x*xzCompression, y*yCompression, z*xzCompression)`
  (свой порт FastNoise/OpenSimplex2S). Это подтверждённая по коду, настоящая **F(X,Y,Z)**, не
  интерполяция хайтмапа.
- **Y — полноценный, но не симметричный вход**: у него свой отдельный коэффициент `yCompression`,
  независимый от общего `xzCompression` для X и Z — то есть даже в этом честном 3D-поле по-прежнему
  сознательно разводят вертикаль и горизонталь отдельными ручками, не считают их взаимозаменяемыми.
- Компромисс производительности устроен неожиданно: точный шум считается только в 4 угловых XZ-колонках
  каждого суб-чанка (но **для каждого Y в диапазоне**), промежуточные X/Z-колонки интерполируются от
  углов — экономят на горизонтали, не на вертикали, в этом конкретном моде.
- Задокументированное трение с движком: отдельный пакет миксинов `mixin/aquiferfix`
  (`AquiferMixin`, `NoiseChunkMixin`, `RandomStateMixin`, `ChunkMapMixin`) — прямое доказательство, что
  ванильный `Aquifer` (раздел 1.3 доки 01) устроен в предположении, что пещеры рождаются из ванильного
  графа плотности, и его пришлось патчить, чтобы он не ломался от стороннего carver-based источника
  пещер. **Конкретный, кодом подтверждённый пример именно того рода "соседних допущений", о которых
  предупреждает таблица раздела 2 доки 01.**

**Значение для брифа:** это единственный во всём исследовании живой, версионно-актуальный (Fabric
1.21.1) мод, реально вызывающий F(X,Y,Z) на каждый блок в продакшене. Он не решает задачу брифа целиком
(это carver поверх ванильной генерации, не полноценный генератор с чистого листа), но как референс для
"первого эксперимента" (раздел 4 брифа) он ближе и полезнее, чем любой материал из Cubic Chunks
(`02-cubic-chunks.md`), просто потому что реально компилируется и работает на целевой версии сегодня.

### Парящие острова / альтернативные измерения

The Aether, StarrySkies, Aetherial Islands — все подтверждены под 1.21.1, Fabric. Внутренний механизм
генерации ни для одного не верифицирован по исходнику в этом проходе (агент прямо пометил как
неподтверждённое, не стоит цитировать технические детали дальше без отдельной проверки). Floating
Island Revived — явный версионный разрыв, 1.21.1 не поддерживается, назван только чтобы не тратить
время на него отдельно.

### Гравитация и неевклидовость — готовые строительные блоки для раздела 9 брифа (6DOF)

Отдельно значимая находка, напрямую бьющая в "третий эксперимент" и вектор-гравитацию из брифа:

- **GravityChanger** (изначально qouteall, архивирован; живые community-форки под 1.21.1) —
  произвольное направление гравитации игрока (`/gravity set_base_direction`,
  `set_base_strength`), гравитационно-активные предметы/блоки (якорь, плитка). **Это физика сущности,
  не генерация мира** — плотности рельефа никогда не касается. Форки не проверены по исходнику на
  полноту под 1.21.1.
- **Immersive Portals** (qouteall/iPortalTeam, ветка `1.21` покрывает 1.21.1, тоже архивирован, "форки
  приветствуются") — портал как настоящий, просматриваемый и проходимый стык между одновременно
  загруженными измерениями/удалёнными участками; README прямо заявляет поддержку "неевклидовых"
  эффектов, и **в связке с GravityChanger поворот портала при проходе меняет направление гравитации
  игрока**. Это ближайший из найденных готовых кирпичиков к "6DOF через несколько/переориентированных
  поверхностей" — но работает на уровне рендера/телепортации/физики, не меняя саму генерацию рельефа.

Оба мода — независимое, готовое подтверждение подхода, который бриф и так предлагает (раздел 9:
гравитация как вектор, отдельно от изменения самого мира) — не нужно изобретать этот механизм с нуля,
можно изучать готовую, работающую реализацию.

## Расширение высоты — три независимых источника сходятся на одном числе

Отдельная таблица находок по модам, расширяющим высоту мира:

- **Extended Build Limit** (Fabric/Forge/NeoForge/Quilt, "1.18–1.21.1") — мод и datapack-вариант,
  без исходника для проверки механизма; вероятно правка `dimension_type` + миксины на потолок
  валидации, не подтверждено.
- **Dynamic Height** (Fabric 1.20–1.21.4, NeoForge 1.21.1) — самая агрессивная находка: ранние сборки
  доходили до ~2060 блоков (упираясь прямо в тот же потолок, что и ниже), а "крупное обновление"
  заявляет экспериментальный диапазон **32 000 блоков** через, по собственному описанию мода,
  "серьёзную переработку вертикального чанк-стриминга, синхронизации окна рендера клиента и обработки
  высоты мира в рантайме" — формулировка, которая звучит как настоящая перестройка хранения/стриминга
  чанк-секций, а не просто ослабленный конфиг-параметр. `[НЕ ПРОВЕРЕНО ПО ИСХОДНИКУ]`, но это прямое
  текстовое описание похоже именно на технику "виртуальный Y с трансляцией координат", которую бриф сам
  предлагает как вариант C в разделе 10 — **стоит отдельного целевого разбора по исходнику**, это может
  быть готовая живая реализация ровно того, что бриф просит исследовать.
- **Shattered World Limits** (Fabric/Forge/NeoForge, "1.21") — имя файла сборки буквально
  `swl-0.0.1-1.21-(Y -2032)-Fabric.jar`.
- **All Dimension Height Increase**, **2032 World Height** — тот же порядок цифр.

**Это третье, полностью независимое подтверждение** числа, уже известного из собственного кода этого
репозитория: `WorldLevels.java` комментирует `min_y ≥ −2032, height ≤ 4064, min_y+height ≤ 2032` как
"абсолютный потолок движка". Теперь то же самое число всплывает в имени файла стороннего, никак не
связанного с DRMD мода. Три независимых источника (свой код, DRMD-специфичный; сторонний мод,
названный в честь этого числа; ещё один сторонний мод, дошедший ровно до той же границы) сходятся на
одном и том же значении — это именно то triangulation, которое требует методология брифа, и в данном
случае она сработала: `−2032`/`4064` можно теперь считать не предположением, а фактом с тройным
независимым подтверждением.

## Кубическая/воксельная генерация и свои `ChunkGenerator` — почти всё мертво, но не без урока

**CubicChunks2** — то же самое, что уже подробно разобрано в `02-cubic-chunks.md`; здесь агент нашёл
дополнительную деталь — по собственному issue-трекеру проекта, поддержка Fabric для 1.17+ была прямо
помечена "не решено" и так и не была реализована — конкретное, отдельное подтверждение вывода doc 02
про отсутствие Fabric-веток.

**Terra 1-to-1 / Terra121** (мёртв, только Forge, MC 1.12.2) — генератор реального рельефа Земли
1:1 из GIS/OSM-данных через свой `ChunkGenerator`. Показательная деталь: **он был построен поверх
Cubic Chunks**, не ванильного хранилища чанков, именно чтобы получить реальные диапазоны высот Земли.
То есть единственный найденный во всём исследовании пример "своего `ChunkGenerator`, делающего
по-настоящему немасштабируемый по хайтмапу рельеф", сам нуждался в Cubic Chunks под собой, чтобы вообще
быть возможным — конкретное, а не гипотетическое свидетельство, насколько несущим является стандартный
потолок высоты чанка для по-настоящему амбициозных генераторов.

**Terra** (PolyhedralDev) — в основном фреймворк для серверных плагинов Paper/Spigot, не обычный
клиент+сервер мод; один Fabric-помеченный билд всплыл в поиске под типом проекта "plugin" — не
проверено независимо, не утверждается как факт.

## Синтез агента (явно отделён от подтверждённых фактов выше)

Почти всё найденное в живой экосистеме Fabric 1.21.x сводится к двум структурным паттернам:

1. **Перенастройка существующего графа плотности на уровне datapack/JSON** (Terralith, Nullscape,
   Aetherial Islands, отчасти Tectonic). Ванильный конвейер уже честно вычисляет F(X,Y,Z) по блоку с
   1.18 — именно поэтому ванильные шумовые пещеры/аквиферы уже могут давать нависания и несвязные
   карманы — но граф намеренно смещён входом "depth", который по умолчанию держит результат в форме
   хайтмапа. Моды этого семейства наследуют и честное 3D-вычисление, и остаточное смещение к хайтмапу
   одновременно, потому что они перепрошивают существующий граф, а не заменяют его.
2. **Миксин-патч в конкретную точку расширения ванили** — сам `NoiseBasedChunkGenerator` (ReTerraForged)
   или интерфейс `WorldCarver` (YUNG's Better Caves) — вместо независимого `ChunkGenerator` с нуля.
   Почти наверняка ради совместимости с экосистемой (структуры, другие worldgen-моды, смешение
   biome source).

**Полностью независимых, написанных с нуля `ChunkGenerator` — ближайшего прообраза "просто
реализовать F(X,Y,Z) самому" — в текущей экосистеме Fabric 1.21.x практически нет.** Два самых явных
исторических примера (CubicChunks2, Terra121) оба мертвы, только Forge, застряли на MC ≤1.17. Это само
по себе значимый вывод для оценки реализуемости: никто из тех, кто сейчас реально поддерживает мод под
Fabric 1.21.x, не брался за "честная 3D-плотность, без потолка высоты" как задачу архитектуры с нуля —
живая экосистема стабильно выбирает остаться внутри (или слегка патчить) существующий,
смещённый-к-колонке ванильный конвейер вместо этого.

## Что это значит для ÆRis (сводка)

1. Ни одна из двух "Fractal World" не даёт готового прецедента честной F(X,Y,Z)-генерации мира —
   кандидат A, похоже, вообще не про это, кандидат B — про это, но не про генерацию (кисть, не
   генератор) и не про актуальную версию (Forge 1.17.1).
2. **YUNG's Better Caves — лучший из найденных живых прецедентов** для "первого эксперимента" брифа:
   реально работает на Fabric 1.21.1, реально вызывает шум на (x,y,z), причём с осознанно разными
   коэффициентами по вертикали и горизонтали — и его собственные миксины на `Aquifer` документируют
   ровно тот класс "соседних допущений", которые ломаются, когда пещеры перестают быть побочным
   продуктом ванильного графа плотности.
3. `−2032`/`4064` как абсолютный потолок движка — теперь подтверждено трижды независимо (свой код +
   два сторонних мода). Можно смело переносить в любой будущий RFC как факт, не как оценку.
4. `Dynamic Height`'s заявленные 32 000 блоков — вероятный кандидат на "виртуальный Y с трансляцией
   координат" (вариант C, раздел 10 брифа) уже в живой реализации, но не проверено по исходнику в этом
   проходе — стоит отдельного целевого чтения кода, если этот вариант станет актуален.
5. GravityChanger + Immersive Portals — не нужно проектировать вектор-гравитацию и неевклидовы стыки с
   нуля для будущих экспериментов с 6DOF, есть на чём проверить идею уже сегодня, хоть и как отдельный
   от генерации мира слой.
6. Главный отрицательный результат раздела: экосистема сама по себе не даёт готового современного
   образца "чистого" кастомного `ChunkGenerator` под Fabric 1.21.x — это подтверждает (не опровергает),
   что "первый эксперимент" брифа — это действительно эксперимент, а не рутинная сборка из готовых
   частей.
